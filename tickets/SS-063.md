## Required technical behavior

### R1

Add explicit collections with ordered audio/image membership, notes, cover preference, and revision-aware membership edits; reference existing assets rather than copy media.

### R2

Implement smart collections from versioned canonical filters; define live membership, ordering, unsupported-filter migration, and no recursion/cycle behavior.

### R3

Add user-defined brand/character kits with palette values, style/reference assets, and optional do/don't notes; distinguish manual character grouping from inferred identity.

### R4

Support add/remove/reorder/bulk membership, rename, duplicate collection definition, and undo where appropriate; deleting collection never deletes originals.

### R5

Authorize each member at query time; counts/covers/previews must not expose inaccessible sources. Missing/offline members are explicit for local management but never export-ready.

### R6

Persist global collections in catalog backups/portable transfer. Single-folder sidecars only include safe source-local subsets or documented references, not global scope leaks.

### R7

Handle asset relocation/replacement and unresolved members in imported collections; do not retarget by filename or similarity.

### R8

Keep image collection navigation separate from audio transport state and provide keyboard reorder/accessibility alternatives.

## Failure, boundary, and verification scenarios

- **T1:** Mixed audio/image collection ordering, smart-filter updates, no recursive membership, and manual character kit boundaries.
- **T2:** Missing/restricted members, source revocation, conflicting edits, portable root mapping, and restore.
- **T3:** Delete/undo collection proves originals, clips, annotations, and usage history remain.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
