## Required technical behavior

### R1

Define a versioned pack manifest with selected asset IDs/content versions, media digests, dimensions/type, recipe/lineage references, source attribution, usage notes, and project-relative filenames.

### R2

Allow explicit original or rendered media choices, destination preview, naming collisions, expected bytes, and prompt/private-note redaction policy; metadata-only catalog export remains a separate action.

### R3

Resolve permissions/current versions for every included item including audio clips and selected images; never crawl sibling files or automatically include all references/parents.

### R4

Produce staged directory/archive using portable safe relative names; reject traversal, reserved device names, case-fold collisions, symlinks, and unbounded paths/entries.

### R5

Verify each media file and manifest before no-clobber publication; cancellation, insufficient space, interrupted packaging, and partial failure have a declared all-or-nothing/recoverable policy.

### R6

Preserve identical-content identities in manifest while optionally deduplicating physical media only with correct references; do not merge annotations.

### R7

Provide read-only manifest validation and a safe unpack/import route if advertised, with decompression/entry limits and no executable preset or script execution.

### R8

Record pack/export history once and document portability after app exit, missing source handling, and unknown usage notes without certifying redistribution rights.

## Failure, boundary, and verification scenarios

- **T1:** Mixed audio/image pack opens in an independent project on supported OSes with relative filenames and correct alpha/dimensions.
- **T2:** Case/Unicode/reserved names, duplicate content, nested traversal/symlink entries, disk-full, cancel, crash, and collision.
- **T3:** Verify checksums, manifest completeness, redaction, scope-limited dependencies, and no secrets/absolute private roots.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
