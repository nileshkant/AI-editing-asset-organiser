## Required technical behavior

### R1

Build a licensed/generated or consented evaluation corpus with provenance covering photos, watercolor, collage, 3D art, screenshots, text, transparent objects, multiple objects, unusual crops, and ambiguous cases.

### R2

Define held-out tagging labels, caption factuality rubric, retrieval queries/relevance judgments, and multilingual coverage actually intended to ship. Record corpus/version/checksums without committing private media.

### R3

Evaluate at least one realistic image-capable caption/tag adapter and one text-image embedding candidate, potentially a combined provider; compare against lexical baseline, resource limits, offline constraints, and cost.

### R4

Check official model/API and license documentation at implementation time; pin model/revision, preprocessing, tokenizer, embedding dimension, normalization, output schema, and supported OS/CPU/runtime. Do not assume current vendor pricing or capabilities from this ticket.

### R5

Set explicit quality/resource acceptance thresholds before final evaluation; publish failures and tradeoffs. Do not choose thresholds after observing the held-out result simply to make it pass.

### R6

Implement bounded reusable adapter interfaces and a reproducible evaluation runner. Store model outputs as untrusted data with schema validation; no tool execution or arbitrary URL fetching.

The evaluation harness runs only on explicitly approved fixture inputs with
an explicit provider/network choice and bounded request allowance. It does
not require SS-052's production queue to exist and must not implement that
later ticket early or process the user's library implicitly.

### R7

Separate self-reported confidence from calibrated measured confidence; use unavailable/uncertain rather than fabricated percentages.

### R8

Choose one initial qualified path for every advertised capability. If CPU-local captioning is not viable, retain cloud-only captioning and a qualified local retrieval pack with explicit scope; do not advertise offline tagging.

### R9

Document installation/download/runtime artifacts for SS-051 and consent/pixel preprocessing for SS-052. Image work does not depend on completing SS-016 audio recognition.

## Failure, boundary, and verification scenarios

- **T1:** Reproduce held-out metrics and actual inference on representative hardware; include memory, latency, per-batch usage, and model input limits.
- **T2:** Adapter tests cover invalid JSON, oversized arrays, missing fields, unsupported input, timeout, provider model removal, and throttling.
- **T3:** Validate frozen embedding vectors/model-space identifiers and retrieval failures on out-of-domain images.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
