## Working design

Permit a user to drop individual audio files without importing their sibling files. Add a source scope that can represent either a recursive folder root or an explicit set of relative file entries. Preserve the same stable sound identity, content-addressed analysis, tags, comments and relocation behavior as folder sources.

## Acceptance criteria

- [ ] Dropping one audio file registers only that file
- [ ] Dropping several audio files registers exactly those files
- [ ] Dropping a folder remains recursive and does not create duplicate identities
- [ ] Unsupported files produce an explicit per-file reason and never block other drops
- [ ] File source scopes can be removed or converted to a folder source only with confirmation
- [ ] Moving a selected file or its containing folder can be relinked without reanalysis when content is unchanged
- [ ] Deleting a selected file marks only that sound missing after a complete reconciliation
- [ ] UI and MCP show the source scope and exact file availability

## Test scenarios

- One file, multiple files, duplicate file path and same content at different paths
- Folder with dot in its name and file with no extension
- Unsupported/corrupt file mixed with valid files
- File rename, parent folder move, volume offline and symlink escape
- Drop cancellation, queue backpressure and duplicate analysis prevention

## Rollout

Until this ticket lands, the UI and native command reject individual file drops with a clear folder-only message. No sibling import is attempted.
