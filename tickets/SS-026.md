## Working design

Permit a user to drop individual audio files without importing their sibling files. Add a source scope that can represent either a recursive folder root or an explicit set of relative file entries. Preserve the same stable sound identity, content-addressed analysis, tags, comments and relocation behavior as folder sources.

## Acceptance criteria

- [x] Dropping one audio file registers only that file
- [x] Dropping several audio files registers exactly those files
- [x] Dropping a folder remains recursive and does not create duplicate identities
- [x] Unsupported files produce an explicit per-file reason and never block other drops
- [x] File source scopes can be removed or converted to a folder source only with confirmation
- [x] Moving a selected file or its containing folder can be relinked without reanalysis when content is unchanged
- [x] Deleting a selected file marks only that sound missing after a complete reconciliation
- [ ] UI and MCP show the source scope and exact file availability (UI and shared core contract verified; live MCP adapter depends on SS-018/SS-019).

## Test scenarios

- One file, multiple files, duplicate file path and same content at different paths
- Folder with dot in its name and file with no extension
- Unsupported/corrupt file mixed with valid files
- File rename, parent folder move, volume offline and symlink escape
- Drop cancellation, queue backpressure and duplicate analysis prevention

## Rollout

Schema v5 upgrades existing recursive-folder sources without changing IDs and creates a pre-migration SQLite backup before its transaction. Selected file jobs persist exact targets and recover with those targets after restart. Scope conversion/removal requires explicit confirmation; dropping an existing selected-files root asks the user to confirm conversion in Settings. No original media is changed.

Evidence and known limitations: [SS-026 review](../docs/reviews/SS-026.md). The live MCP half of the final acceptance criterion remains open until SS-018/SS-019 implement that adapter; its source scope/availability contract already comes from the shared core.
