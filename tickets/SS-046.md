## Required technical behavior

### R1

Support user tags, notes, favorites, nullable ratings with a documented scale, and tag rename/alias operations; normalize whitespace/case consistently with audio while preserving display spelling.

### R2

Keep user facts separate from future AI suggestions and machine-derived technical fields. Never overwrite creator annotations during reimport or content replacement.

### R3

Use optimistic revision checks and explicit add/remove/replace operations; avoid full-array replacement silently losing another editor's tags.

### R4

Provide bounded batch selection, count/preview, per-item results, and reversible action history. Define transaction/partial-failure policy and undo conflicts if later changes exist.

### R5

Specify whether global rename applies across permitted source scopes and both media kinds; preview affected counts and preserve a reversible migration of aliases.

### R6

Treat notes/tags as plain text with size limits; do not render raw HTML or execute content. Distinguish absent rating from zero.

### R7

Immediately invalidate relevant search/inspector caches, mark source snapshots dirty through the shared path, and define serialized annotation/revision payload for SS-048.

### R8

Require current asset identity and source scope; same-content copies can carry different annotations.

## Failure, boundary, and verification scenarios

- **T1:** Test Unicode normalization, case duplicates, long values, empty/removal behavior, aliases, and rating limits.
- **T2:** Race user edits and batch/undo operations; restart mid-batch and verify the declared transaction policy.
- **T3:** Reimport/replacement and duplicate-content fixtures retain independent annotations; verify XSS-like notes stay plain text.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
