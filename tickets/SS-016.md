## Working design

Opt-in audio-capable recognition must produce specific searchable sound-event
labels, not merely intensity/tempo/texture measurements. Examples include rain,
thunder, footsteps, engine, bird calls and hiss; more specific labels such as
heavy rain or car engine require supporting evidence. Do not infer rain solely
from broadband noise. Multiple events may coexist; unknown/unrecognizable audio
must remain unknown. Filename hints cannot be presented as listening results.

Enrichment runs as a separate resumable job after import when enabled. Baseline
analysis publishes without waiting for AI. Use taxonomy IDs, readable labels,
search aliases, model/version, content hash, coverage/time ranges and confidence
or uncertainty with each suggestion. Preserve user accepted/rejected corrections;
do not recreate rejected suggestions for the same model/content revision.

SS-016 owns shared enrichment storage/jobs, cloud audio-capable recognition and
UI/MCP search integration; SS-017 owns offline model distribution/inference and
uses the same result contract. MCP tools expose recognition results and may
request authorized jobs; connecting MCP does not itself recognize audio.

## Acceptance criteria

- [ ] Audio upload separately consented.
- [ ] capability verified per model.
- [ ] Claude text-only metadata path never claims listening.
- [ ] suggested tags not overwrite user tags.
- [ ] resumable version-keyed enrichment.
- [ ] uncertain predictions visible.

- [ ] Specific event labels generated on enabled imports with provenance; measured tags remain separate.
- [ ] Labels and aliases searchable/filterable in UI and MCP with identical authorization/ranking.
- [ ] Details expose suggested/accepted/rejected states, model/content version, coverage and uncertainty.
- [ ] Rain/hiss/thunder/footsteps/engine/mixed/silent/unknown fixtures have a labeled evaluation corpus, per-class precision/recall and published limits.
- [ ] Human corrections survive reanalysis, sidecar reuse/reimport and enrichment retries.
- [ ] No-model/key, unsupported model, quota/timeout and rejected consent preserve working audio import and search.
- [ ] Jobs prioritize import/playback, deduplicate by content/model version and respect cancellation/cost limits.

## Test scenarios

- Unsupported audio.
- upload size limits.
- sampled vs whole coverage.
- wrong model/key.
- sanitized metadata.
- changed file.
- fabricated response.
- consent revocation.
