## Required technical behavior

### R1

Inventory the actual merged schema, source snapshot, portable envelope, IPC names, and MCP capabilities; current planning baseline is SQLite v9, but read main rather than hard-code that assumption.

### R2

Create docs/IMAGE_CONTRACTS.md and serializable Rust/TypeScript contract fixtures for asset header, image technical profile, availability, enrichment state, evidence, annotation revision, image recipe, and derived lineage. Reserve derived element kind without implementing extraction.

### R3

Use asset identity distinct from content digest. Specify existing sound IDs remain unchanged; image/element IDs cannot collide with audio. Define source ID plus normalized relative path membership and explicit-file scope behavior.

### R4

Define technical state pending/ready/failed independently from AI state disabled/queued/running/complete/failed/cancelled/stale. Availability offline/missing/inaccessible is not a decode state; unknown fields are nullable rather than zero.

### R5

Choose canonical displayed-image coordinates after EXIF orientation; describe raw versus oriented dimensions, pixel centers, inclusive/exclusive bounds, normalized coordinates, and alpha/color conventions for future crops/masks.

### R6

Define schema-version negotiation, unknown asset-kind handling, explicit downgrade refusal, portable metadata versus backup versus media-pack boundaries, and legacy audio-only consumer behavior. Future fields cannot be silently discarded.

### R7

Specify validation limits for paths, captions, tags, metadata blobs, dimensions, job payloads, and thumbnails with named configurable constants; use checked integer products and describe pagination ordering.

### R8

Define domain error codes and Rust/IPC serialization examples, including camelCase invocation arguments, stable enum strings, numeric ranges safe in JavaScript, null/absent behavior, and expected revisions.

### R9

Add synthetic mixed-catalog fixtures and compatibility tests for current audio contracts; no real user database or licensed media. Document which later ticket owns each schema/capability.

## Failure, boundary, and verification scenarios

- **T1:** Round-trip valid/invalid fixtures through Rust serializers and TypeScript contract validation.
- **T2:** Snapshot existing sounds.*, clips.*, portable audio responses; reject unknown enum values and wrong asset kinds with documented errors.
- **T3:** Test Unicode paths, unsafe relative components, nonfinite numbers, overflow dimensions, missing optional fields, and future schema rejection.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
