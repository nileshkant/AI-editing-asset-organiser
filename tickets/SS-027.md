# SS-027: macOS 26 native startup compatibility

## Goal

SoundShelf must open as a native Tauri window on macOS 26 Tahoe on Apple Silicon.

## Context

The macOS 26 AppKit lifecycle can raise an Objective-C exception while `tao`
0.35.3 is still inside `applicationDidFinishLaunching`. Because the initial
Tauri event is dispatched from that non-unwinding callback, the process aborts
before the WebView becomes usable.

## Acceptance criteria

- The initial Tauri event is dispatched on the main dispatch queue after the
  AppKit launch callback returns.
- The compatibility patch is isolated to the vendored `tao` dependency and
  can be removed when an upstream release contains the fix.
- Rust unit and integration tests remain green.
- A release macOS build completes and the native process does not immediately
  abort during startup.
- A bundled app without optional media resources still opens; missing resource
  directories must disable media tools rather than abort setup.
- The workaround does not change the application API or catalog behavior.

## Verification

- `CARGO_NET_OFFLINE=true node scripts/cargo.mjs test --workspace`
- `node scripts/desktop.mjs build --bundles app`
- Launch the rebuilt native executable and verify it remains alive without the
  `tao::platform_impl::platform::app_delegate::did_finish_launching` abort.
- Launch the packaged `.app` and verify the SoundShelf Library window opens.

## Follow-up

Replace `vendor/tao` and the workspace patch with the first upstream `tao`
release that includes the macOS 26 lifecycle fix, then rerun the desktop smoke
test on macOS 26 and an earlier supported macOS version.
