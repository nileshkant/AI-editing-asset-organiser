## Required technical behavior

### R1

Define a structured brief with scene IDs/text, required asset roles, frame/output intent, style/kit references, and source/usage filters; support manual entry without an AI text provider.

### R2

If using AI to parse prose, qualify the text capability separately, disclose brief upload, reuse provider/budget controls, and validate output against a bounded schema.

### R3

Query canonical library search per scene/role and provide limited candidates with actual ID/version, preview, match evidence, output-fit warnings, and explicit unsatisfied constraints.

### R4

Never fabricate an ID, assume a missing file exists, claim visual inspection from tags alone, or silently relax dimensions/usage/source restrictions to fill every scene.

### R5

Allow preview, pin, reject, replace, and reorder candidates; preserve user-selected decisions across rerun with clear stale/missing warnings.

### R6

Use collections/kits and confirmed character references to encourage consistency, but present similarity as a suggestion rather than a guarantee of identity.

### R7

Persist brief revision, candidate snapshot, selection revisions, and provenance without storing private script text in public manifests by default.

### R8

Add cost/cancellation limits for multi-scene searches/AI calls and scope-check every candidate on retrieval/export; no auto-generated video or automatically executed project code.

## Failure, boundary, and verification scenarios

- **T1:** Five-scene brief with suitable matches, missing-role gap, conflicting requirements, and multiple reference styles.
- **T2:** Malformed/instruction-injected AI output, unauthorized asset ID, changed content after shortlist, and cancelled batch.
- **T3:** Manual-only flow, user pin preservation across rerun, revision conflicts, and private brief export redaction.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
