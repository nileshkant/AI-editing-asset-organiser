## Working design

## Acceptance criteria

- [ ] Every requested feature has a ticket.
- [ ] no audio or credentials tracked.
- [ ] each implementation branch has test and review evidence.
- [ ] no claim of PR publication without a remote.

## Test scenarios

- Audit git tracked paths.
- inspect dependency ordering.
- validate ticket metadata and unique IDs.

## Review and completion

Review correctness, failure recovery, file safety and privacy. Record commands and actual outcomes in docs/reviews/SS-001.md. Do not mark complete merely because the UI control exists. Record platform limitations and deferred criteria explicitly. Each fix discovered during review remains scoped to this ticket or gets a follow-up ticket/branch.

## Rollout

No source media mutations. Any persistent-schema change requires a transaction, migration test and compatible rollback or pre-migration backup. Feature flags remain off until their acceptance checks pass.
