## Required technical behavior

### R1

Register verified SS-076 outputs as element assets with independent ID, content version, actual path/source grant, dimensions/alpha, parent asset/version, mask/recipe revision, and export lineage.

### R2

Registration of one approved file must not grant access to its siblings or parent image. Define a narrow file source or explicit existing-source membership; preserve authorized destination boundaries.

### R3

Make publication/registration recoverable: committed PNG with failed indexing remains valid and can be registered by a retry without rendering another file or duplicating identity.

### R4

Give child user annotations their own lifecycle. Inherit source/attribution/restrictions and explicitly applicable subject labels; do not blindly inherit forest/background/other-object tags.

### R5

Allow optional cutout-specific analysis through consented queue; record element-only coverage and avoid copying parent AI results as though pixels were reanalyzed.

### R6

Show original/derivative navigation only when authorized. Parent offline or deleted does not invalidate existing rendered PNG; source replacement marks regeneration recipe stale.

### R7

Extend search/kind filters/collections/duplicate handling/usage/packs/MCP get/preview/resolve/export to elements with identical scope rules; metadata cannot leak a restricted parent.

### R8

Persist lineage across backup, portable transfer, source-folder catalogs, and packs using resolvable IDs with explicit unavailable-parent state. Single-folder export must not pull unauthorized ancestors.

### R9

Support explicit re-extraction as a new revision/output with no silent overwrite; define child archival/removal versus original-file deletion and guard cyclic/self lineage.

## Failure, boundary, and verification scenarios

- **T1:** Export→register→search transparent subject→MCP preview/export→independent project reuse without selecting mask again.
- **T2:** Parent unavailable/restricted/replaced, child moved, new content at old child path, missing mask, lineage cycle, and retry after indexing failure.
- **T3:** Independent annotations, filtered inherited tags, portable pack/backup round-trip, and no sibling grant or parent metadata leak.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
