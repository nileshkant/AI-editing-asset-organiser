## Required technical behavior

### R1

Implement provider/model configuration with an explicit capability registry for image input, structured output, embeddings, and local endpoints; text support does not imply image support.

### R2

Reuse any SS-014 implementation that exists at execution time. Otherwise extract its shared credential/configuration subset here, update SS-014 cross-references, and leave unimplemented provider/audio criteria unchecked.

### R3

Store keys in OS credential storage or memory for session-only mode; never renderer storage, ordinary catalog DB, portable metadata, diagnostic logs, or export manifests.

### R4

Support explicit local endpoint opt-in, HTTPS for remote providers, URL validation, redirect policy, TLS errors, and local/private network restrictions appropriate to configured endpoints; do not permit image metadata to select an endpoint.

### R5

Connection tests are explicit and distinguish authentication, model existence, image capability, schema compatibility, timeout, quota, and rate-limit failure. Do not upload user images in a connection test.

### R6

Define a provider adapter trait with bounded requests/responses, timeouts, sanitized errors, model version metadata, and usage reporting; concrete production image adapter is qualified in SS-050.

### R7

Handle keyring denied/unavailable, rotate/delete key, endpoint/model changes, app restart, and in-flight configuration changes without falling back to a different provider silently.

### R8

Document source-specific consent as separate from key configuration; no network analysis starts here. Avoid duplicating service-owned settings in the renderer.

## Failure, boundary, and verification scenarios

- **T1:** Provider configuration validation and mocked wire errors, malformed URLs/redirects, local opt-in, keyring failure, and secret rotation.
- **T2:** Audit logs/diagnostics/DB/portable exports/UI error text for keys; assert disabled startup performs no provider requests.
- **T3:** Verify configuration changes fence old jobs and unsupported image capability is distinguishable from invalid credentials.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
