## Working design

Audio v1 final release gate. Assemble evidence for one concrete signed candidate
on a deliberately declared platform/architecture matrix. No AI key, model pack,
image import or preset support is needed for the baseline audio release.

## Acceptance criteria

- [ ] Record artifact checksum, commit, dependency lock, supported OS/CPU and installer signature/notarization evidence.
- [ ] Clean machine/offline install starts without workspace, Node, Rust or separately installed media tools.
- [ ] Source reference/import/catalog reuse/pruning/relink/tag/comment/favorite/search workflows pass in installed app.
- [ ] Human listening/output-device tests verify play/pause/seek/loop/device recovery; clip exports verified in an independent editor.
- [ ] A real scoped MCP client completes initialize/search/get/create/export/status, restart/reconnect and revocation with the installed bridge.
- [ ] Restore populated backup, upgrade, interrupted import/export, disk-full and uninstall boundaries verified.
- [ ] SS-023 security, accessibility, long-session/resource and performance evidence covers the candidate.
- [ ] Installer contents contain zero source recordings; report compressed/uncompressed package size and cache/export footprint separately.
- [ ] No unresolved critical/high severity defect in required workflows; lower issues have documented impact/workaround and release decision.
- [x] Tester instructions, sample tasks, local redacted diagnostics, feedback template, known limitations and recovery steps are provided.
- [ ] Any optional capability shipped has its own acceptance evidence; absent AI recognition is disclosed clearly.

## Test scenarios

Fresh install and populated upgrade; ordinary user permissions; offline core use;
real external-drive disconnect; malformed media; mixed imports during playback;
MCP read-only and export scopes; source-catalog crash recovery; signed artifact
launch after download. Record observed outcomes, not just commands or mock passes.
A tester release is not a claim of universal platform production readiness.

## Review and completion

Record evidence and limitations in docs/reviews/SS-031.md. Mark acceptance
only after verification. Source audio bytes must never be changed. Schema or
identity changes require transactional migration and recovery evidence.
