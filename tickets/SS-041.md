## Required technical behavior

### R1

Implement the SS-040 additive schema and transactional upgrade; preserve existing sounds, clip IDs/revisions, annotations, source grants, jobs, and settings. Avoid rewriting legacy sound identity as a content hash.

### R2

Add typed image records, content versions, technical-profile references, annotation revisions, and reserved derivative lineage structures only where justified by contracts; add foreign keys, unique membership constraints, and query indexes.

### R3

Reuse analysis by content plus analyzer version, while separate identical files keep independent identity and user annotations.

### R4

Specify same-path replacement, rename, root relocation, overlapping sources, and multiple file scopes. Do not guess that a similar-looking or renamed file is the same asset; ambiguous moves require explicit reconciliation.

### R5

Create a consistent pre-upgrade backup before mutating a persistent catalog. Reject newer schemas; document supported restore/downgrade procedure and fail if backup cannot be made.

### R6

Keep writes bounded and transactional; separate long file work from DB locks. Add asset-kind validation at repository/service boundaries.

### R7

Initially keep image capability gated. Prevent legacy audio-only source snapshot writers from overwriting a source containing image records; mixed persistence is completed in SS-048.

Include bounded ID/version get and stable paginated image-list repository
operations for the later gallery. These are basic catalog reads, not the
full-text/filter/ranking service assigned to SS-058.

### R8

Ensure failed migrations leave original data readable by the previous compatible binary and do not orphan source memberships; include integrity/foreign-key checks.

## Failure, boundary, and verification scenarios
