## Required technical behavior

### R1

Store source URL/provider, creator, acquisition/reference identifier, attribution text, license reference/version/date, project restrictions, and reviewed-by-user state.

### R2

Use explicit unknown/unreviewed states; labels describe user records rather than application-certified legal clearance or ownership.

### R3

Allow batch assignment with scope preview, per-asset overrides, revision conflicts, and recoverable history; avoid assigning one source/license to unrelated files silently.

### R4

Do not derive rights from generation status, filename, watermark detection, or image content. Links are inert data until a deliberate user open action.

### R5

Define derivative inheritance: source/attribution/restrictions persist; child-specific notes can be added without silently deleting parent conditions.

### R6

Add inspector and filter-ready structured fields; negative/unknown values must remain distinct from approved/project-permitted.

### R7

Extend all persistence paths, manifest schema, and privacy redaction controls. No remote license scraping or approval workflow required to use basic local browsing.

## Failure, boundary, and verification scenarios

- **T1:** Unknown versus user-reviewed states, conflicting bulk updates, restore/reimport, and source-content change.
- **T2:** Malicious URLs/markup in attribution remain inert; large fields rejected without data loss.
- **T3:** Round-trip attribution/restrictions and synthetic derivative inheritance fixture.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
