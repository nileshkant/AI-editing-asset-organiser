## Required technical behavior

### R1

Version source-folder and portable envelopes using SS-040 contracts; round-trip image identity/version, technical facts, user metadata/revisions, and slots for later evidence/recipes without changing audio payload meanings.

### R2

Implement bounded schema parsing, validation, source mapping preview, collisions, and atomic imports. Unknown newer kinds/required fields fail visibly rather than disappear.

### R3

Preserve source snapshot revision locking, dirty/retry state, atomic replacement, read-only behavior, and original-file immutability; remove SS-041 temporary guards only when mixed snapshots are proven safe.

### R4

Retain listed-file warm import with no rediscovery/hash/decode of unchanged compatible content; explicit Refresh finds new members and exact verification handles same-stat replacement.

### R5

Define durable versus rebuildable records: annotations/evidence/recipes in metadata; thumbnails/embedding indexes/model binaries rebuilt or separately managed. No credentials, raw grants, absolute roots, or media bytes in portable exports.

### R6

Extend WAL-consistent DB backups, upgrade recovery, source-snapshot reconciliation, and restore preview. Restoring an older backup cannot silently overwrite newer sidecar annotations.

### R7

Specify bounded envelope size/count limits based on existing distinct folder/portable limits; never truncate records to fit. Document missing external media after metadata-only restore.

### R8

Add migration/export hooks so later tickets must extend all serialization/restore paths as they add fields. A field cannot ship durably only in SQLite.

### R9

Permit gated local image library exposure after verified round-trip and audio regression; do not advertise yet-unimplemented AI/MCP image capability.

## Failure, boundary, and verification scenarios

- **T1:** Mixed library round trip, source relocation, fresh-machine root mapping, read-only source, conflicting revisions, and unsupported future schema.
- **T2:** Disk-full/crash during snapshot and restore, backup with active WAL, missing originals, and corrupted/oversized envelopes.
- **T3:** Instrument warm reuse to prove no unnecessary decode/hash; compare annotations/IDs/audio clips before and after restore.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
