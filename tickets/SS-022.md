## Working design

Audio v1: organized settings, cache/resource controls, database backup/restore
and a redacted support bundle. Provider setup SS-014 is optional and does not
block baseline settings. Distinguish DB backup, source-folder metadata snapshots,
waveform caches and exported audio; diagnostics must not collect source media.

## Acceptance criteria

- [x] Folders editable.
- [x] output device and worker limits.
- [x] AI consent controls only if AI ships; baseline clearly states recognition unavailable without an enabled model.
- [x] cache rebuild distinct from analysis reset.
- [x] backup consistent WAL snapshot.
- [x] destructive actions confirmed.
- [x] no recordings/keys in diagnostics.

- [x] Source catalog reuse/refresh/rebuild and read-only/dirty snapshot warnings explained.
- [x] Backup/restore reconciles source metadata revisions without overwriting newer user annotations.

## Test scenarios

- Restore/version mismatch.
- disk-full backup.
- concurrent jobs.
- settings migration.
- redaction.
- cache purge during playback.
- reset cancellation.

## Review and completion

Review correctness, failure recovery, file safety and privacy. Physical device switching/recovery, disk-full database restore and populated installed restart remain SS-031 qualification gates. The worker limit is deliberately one; queued imports can be paused. Analysis reset is not exposed.

Record commands and actual outcomes in docs/reviews/SS-022.md. Do not mark complete merely because the UI control exists. Record platform limitations and deferred criteria explicitly. Each fix discovered during review remains scoped to this ticket or gets a follow-up ticket/branch.

## Rollout

No source media mutations. Any persistent-schema change requires a transaction, migration test and compatible rollback or pre-migration backup. Feature flags remain off until their acceptance checks pass.
