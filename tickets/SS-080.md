## Outcome and necessity

Col decided on 20 October 2026 that AI tagging without an API key should work
the way it does for audio: an AI client connected over MCP reads images and
writes tags. This slice gives that path now, using services that already exist
(gallery index, previews, SS-046 annotations). It does not replace
[SS-067](SS-067.md) or [SS-068](SS-068.md); those later extend the same tools
with search ranking, resources, import and export.

## Required behavior

- **R1:** Add `images.search`, `images.get`, `images.preview` and
  `images.annotate`. All `sounds.*`, `clips.*`, `jobs.*`, `catalog.*` names and
  payloads stay unchanged.
- **R2:** Apply the client's source scope before matches, totals, previews and
  errors. A denied ID fails exactly like an unknown one. Caller identity comes
  from the authenticated transport.
- **R3:** Pixel disclosure is a separate permission (`previews`), off for
  existing pairings. Metadata read never implies pixels. Annotation needs
  `edit`.
- **R4:** Previews are bounded (at most 512 px on the long edge), served through
  the existing preview service with version checks, and returned as MCP image
  content within the existing 2 MiB response budget. Absolute paths are never
  returned.
- **R5:** Annotation is revision- and version-checked, recorded in the undo
  history labeled as an MCP client edit, and limited to adding and removing
  tags. Notes stay private to the owner; captions and AI evidence persistence
  remain SS-053.
- **R6:** Search uses indexed catalog rows (no filesystem scan), has bounded
  pagination, and supports text, tag and untagged filters. Measure it on a large
  catalog.
- **R7:** Settings lets the owner grant previews per client. The MCP guide
  documents a tagging workflow that treats catalog text as data and never
  claims to have seen pixels it did not fetch.

## Acceptance criteria

- [x] **A1:** An authorized MCP client can find untagged images, view a preview and add tags, end to end over the real transport.
- [x] **A2:** Scope, permission, stale-version and revision failures are distinct and leak nothing outside scope.
- [x] **A3:** Existing pairings gain no pixel access; audio tool surface unchanged.
- [x] **A4:** Large-catalog search time measured; checks pass; review note written.
- [ ] **A5:** This ticket has its own PR with all checks passing on its current head.
