## Working design

Allow a user who does not configure an AI API key to use the same SoundShelf tools through an AI client subscription, where that client supports the required MCP transport and permissions. The desktop app remains the local source of truth and the feature does not proxy audio to a cloud model by default.

The app exposes one capability-checked MCP service and generates setup instructions/configuration for each client:

- Claude Desktop/Claude Code: provide a local stdio bridge to the running SoundShelf app, or a loopback HTTP endpoint where the client supports it. Claude's local server configuration is opt-in and must be removable without editing unrelated configuration.
- ChatGPT: support the client only through a remote MCP endpoint or an OpenAI-supported Secure MCP Tunnel. ChatGPT does not connect directly to a local MCP server. Subscription access, plan, workspace developer mode, admin approval and product surface determine whether the user can enable it. ChatGPT custom MCP must not be represented as an API-key-free local connection.
- Other MCP clients: show the standard streamable HTTP/stdio details and a copyable configuration only after the app has issued a scoped pairing token.

The client sees the same search, sound details, facets, clip recipes, export jobs and explicit annotation tools as the UI. Audio bytes remain local unless the user explicitly requests an allowed export/share action. A client using only read/fetch permissions cannot create annotations or exports. The desktop app must be running; closing it invalidates the local service. A tunnel is a user-controlled deployment concern and is never started silently by SoundShelf.

Reference capability documentation:

- OpenAI: https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt
- OpenAI connection setup: https://developers.openai.com/docs/remote-connections
- Anthropic MCP overview: https://docs.anthropic.com/en/docs/mcp
- Anthropic MCP client configuration: https://docs.anthropic.com/en/docs/claude-code/mcp

## Acceptance criteria

- [ ] Settings shows separate Claude local, ChatGPT remote/tunnel and generic MCP connection states
- [ ] No API key is requested or implied for a subscription-backed client connection
- [ ] ChatGPT setup explicitly explains that local MCP is unsupported directly and requires a supported remote endpoint or secure tunnel
- [ ] Claude setup produces a reversible stdio configuration using the installed SoundShelf bridge, with no shell interpolation
- [ ] Setup never writes client configuration without a visible confirmation and a backup/restore path
- [ ] Pairing uses a scoped, revocable token; tokens are not stored in SQLite, logs, screenshots, exports or renderer storage
- [ ] The MCP server binds to loopback by default; remote/tunnel mode requires an explicit user action and displays the exposure scope
- [ ] Read tools, annotation tools and export tools have separate permissions and client-visible descriptions
- [ ] The service rejects a client after SoundShelf fully quits and accepts it again only after a new pairing/launch state
- [ ] UI and subscription-backed MCP return the same search ranking, availability, metadata provenance and job states
- [ ] Missing/offline/deleted sounds are never returned as playable ready media
- [ ] Natural-language search works offline through the same deterministic search service; AI query interpretation remains explicitly optional
- [ ] Audio is never uploaded merely because the client has an active subscription
- [ ] The feature has a client compatibility matrix and a user-facing troubleshooting path for plan/admin/transport restrictions

## Test scenarios

- Claude stdio handshake, tool listing and graceful reconnect after app restart
- Claude configuration preview, confirmation, backup and removal without modifying unrelated JSON
- ChatGPT setup with no tunnel explains the remote requirement and does not expose a LAN port
- ChatGPT tunnel setup is represented as a documented external prerequisite; no credentials are captured by SoundShelf
- Pairing token scope, expiry, revocation, replay and concurrent-client limits
- Origin/Host validation, loopback bind, remote bind denial and malformed MCP arguments
- Read-only client cannot annotate or export; write client receives confirmation semantics
- UI/MCP parity for typo search, tags, comments, favorites, folders moved and deleted sounds
- App quit invalidates clients and terminates pending jobs according to the normal shutdown policy
- No audio data leaves the machine during metadata-only search and catalog browsing
- Client/model subscription errors are shown as client capability errors, never as missing SoundShelf files

## Review and completion

Review protocol security, client-plan claims, permission boundaries, config-file safety, tunnel exposure and privacy. Verify the current vendor documentation before release because subscription and MCP availability can change. Record real client versions and plan/workspace requirements in `docs/reviews/SS-025.md`. Do not claim that a ChatGPT subscription is equivalent to an OpenAI API key.

## Rollout

Feature is disabled until SS-018 authentication, SS-019 tool scopes and SS-024 installer/security checks pass. Default is local-only MCP with no remote transport. Client setup is an explicit user action, and revocation must be available from SoundShelf Settings.
