## Required technical behavior

### R1

Add image annotation/crop-recipe create-update and export commands using ID/content version/expected revision; add job status and caller-owned cancellation with bounded pagination.

### R2

Agent import takes a native-approved selection grant bound to client, exact source/files, allowed kinds, expiry, and use/retry policy; arbitrary root/path arguments cannot replace the grant.

### R3

Reuse SS-043 import and SS-052 enrichment services. Import approval does not grant cloud upload or allow an agent to enable models/providers silently.

### R4

Reuse single-destination SS-065 export grants with explicit selected format/path scope; client cannot borrow another client's grant or overwrite a file.

### R5

Separate read, preview, annotation, crop editing, import, export, and source-path permissions; migrate pairings conservatively and recheck revocation at dispatch and publication.

### R6

Specify idempotency by client/operation/key and validated arguments; persist or explicitly report restart-unknown states so retries cannot silently duplicate imports/exports or billing.

### R7

Restrict job visibility/cancellation to owned operations; do not let an agent cancel another user's shared import or leak active filenames from ungranted sources.

### R8

Handle annotation merging, concurrent revision conflicts, stale recipes, quota, destination expiry, service shutdown, and committed-but-indexing-failed results without false success/failure.

### R9

Update SS-039 ownership: approved-selection infrastructure is reusable, but its audio understanding requirements remain open. Update image-agent workflow with end-to-end export and verification.

## Failure, boundary, and verification scenarios

- **T1:** Real client native-grant → import/status → search/preview → annotate/crop → export/status → independent-project use.
- **T2:** Permission matrix and revoked/expired/cross-client grants; arbitrary paths, symlink replacement, stale versions, and conflicting revisions.
- **T3:** Identical/different-argument retries, dropped connection/restart, publication cancellation race, and unchanged audio tools.
- **T4:** Apply the shared contract's relevant authorization, concurrency, cancellation, persistence, recovery, resource, and accessibility checks. Record a reason for any genuinely inapplicable category.
- **T5:** Verify impacted legacy audio behavior and ensure original media hashes are unchanged. Use real media/native/client tests for media/platform claims, not mocks alone.
