# SS-035: Windows media console flashes

Status: partial
Branch: fix/SS-035-windows-media-console
Depends on: 004,010,011,013,024

## Report

The alpha.4 Windows build briefly opens a terminal during imports and waveform
selection. FFmpeg/FFprobe are console executables; piping their output does not
prevent Windows from allocating a console.

## Acceptance

- [x] Shared import/waveform/export stream runner uses CREATE_NO_WINDOW on Windows.
- [x] Independent playback decoder (including seeking) uses the same policy.
- [x] Arguments, output pipes, watchdog, cancellation and failure handling retained.
- [x] Windows-native child tests observe no console and working stdout/stderr.
- [x] Native media regression suites pass on Windows, macOS and Linux CI.
- [ ] Tester verifies no flashing/focus theft using the exact installed Windows EXE.

## Tester procedure

Launch from Explorer, with no developer terminal attached. Record the version,
installer SHA-256, Windows version and display scaling. Import a disposable mixed
WAV/MP3/FLAC folder, select each sound, repeatedly click/drag its waveform, seek
during playback, pause/resume, stop, and export WAV/FLAC. Repeat at 100% and 150%
scaling, including an invalid recording and import cancellation. Expect no new
terminal window and no focus theft; errors stay in the application. Capture a
screen recording of the sequence. This cannot be certified visually on a Mac.

No source audio or schema changes. Signing and Gatekeeper remain separate.
