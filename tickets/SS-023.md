## Test scenarios

- Fuzz parsers/MCP/path/selection.
- malicious filenames.
- SSRF/origin checks.
- dependency scan.
- high CPU.
- long sessions.
- memory and crash recovery.

## Review and completion

Review correctness, failure recovery, file safety and privacy. Record commands and actual outcomes in docs/reviews/SS-023.md. Do not mark complete merely because the UI control exists. Record platform limitations and deferred criteria explicitly. Each fix discovered during review remains scoped to this ticket or gets a follow-up ticket/branch.

## Rollout

No source media mutations. Any persistent-schema change requires a transaction, migration test and compatible rollback or pre-migration backup. Feature flags remain off until their acceptance checks pass.

## Qualification boundary

Implementation hardening and repeatable fixtures are reviewable. Sustained fuzzing, worst-case profile memory, installed accessibility/audio/client stress and long sessions remain release gates. RustSec glib unsoundness is tracked in SS-034; Linux release support stays blocked. Do not mark complete from unit/CI passes alone.

Remaining qualification gates:
- [ ] Sustained coverage-guided parser/media/MCP fuzzing.
