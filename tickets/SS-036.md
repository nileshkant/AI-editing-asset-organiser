## Report and scope

Alpha.4 Settings is a crowded single page. Organize the existing audio settings
into Sources, Catalog data, Audio & recovery, Agent access and Application panes.
Use platform system fonts, native form controls, descriptive groups, readable
paths, wrapping actions and keyboard navigation. This shared Tauri web UI follows
common desktop preferences conventions; it is not a native SwiftUI/WinUI/GTK
settings window or a claim of complete platform HIG certification.

## Acceptance

- [x] One visible named pane; Arrow Left/Right, Home/End and Tab navigation.
- [x] Switching panes preserves import previews, client forms and recovery state.
- [x] Destructive source operations retain confirmation and focus restoration.
- [x] Controls and paths fit the 720x560 minimum app window in browser inspection.
- [x] Release version uses Tauri package metadata and is not labelled Development.
- [x] Frontend regression and production build pass.
- [ ] Installed macOS, Windows and Linux keyboard/screen-reader/scaling checks.

## Testing team handoff

Use the exact new installer, not alpha.4. Record OS, version, installer hash,
display scaling and assistive technology. Check 1280x820 and 720x560 windows,
100%/150%/200% scaling and long source names/paths. Visit every category, scroll
to its last action, and confirm no clipped labels or unreachable buttons. Use
Tab/Shift-Tab, Left/Right, Home/End and Space/Enter. Check VoiceOver, Narrator or
Orca announces selected tabs and controls. Cancel source removal/restore/rebuild
without changing data. Use disposable sources for destructive positive tests.
Open a catalog preview and fill the MCP client name, switch categories, return,
and verify state remains. Native file dialogs, permissions, physical audio and
the OS-specific webview still require installed testing. Pair only test clients.
