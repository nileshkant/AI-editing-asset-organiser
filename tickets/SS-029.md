## Working design

Audio v1 requirement. Write `.creativeshelf/catalog.json` inside a writable
folder source after successful import. SQLite remains the live query database;
the sidecar is a versioned per-folder metadata snapshot, never copied audio.
SS-021's explicit portable import/export is a reusable foundation, not completion
of this automatic path. File-only imports remain scoped and do not catalog siblings.

The sidecar contains source-relative paths, stable identities, content versions,
stat fingerprints, measured profiles, machine tags with provenance, user tags,
comments, favorites and source-local clip recipes with required revisions.
Waveform reconstruction requirements are explicit; never mark incompatible or
incomplete analysis ready. Exclude secrets, absolute paths, global saved searches,
foreign sources and application jobs/settings. Bound bytes/entries and validate
schema, membership, numeric fields, traversal and symlink containment before use.
Treat metadata as data, never instructions or a filesystem grant.

On folder import, check the sidecar first. A valid compatible catalog supplies
members directly: no recursive discovery, content hashing or decoding of unchanged
listed files. Cheap existence/stat checks of listed paths are required. Merely
having a file is insufficient to trust malformed or unsupported metadata. Report
invalid catalogs with explicit rebuild recovery; do not silently consume them.
Changed listed fingerprints enqueue only affected files; explicit Refresh discovers
new/unlisted files. A same-size/same-mtime replacement needs explicit content
verification; never promise perfect change detection from stat checks alone.

Prune an entry only when its absence is confirmed within a reachable readable
root. Missing entries disappear from the sidecar and ready UI/MCP results; retain
DB identity/annotations and stale recipe history for recovery. Offline drives,
permission errors, incomplete scans, decoder failures and cancellation must not
prune entries. Revalidate current availability before playback or export.

Write snapshots atomically via a staged file and replace, with revision/conflict
checks so two apps cannot overwrite newer metadata. Preserve the previous valid
catalog on interrupted writes, disk full or cancellation; persist a dirty/retry
state if DB and sidecar diverge. Serialize snapshot updates without holding a DB
transaction during I/O. A read-only source still imports using the local DB with
a visible warning that its portable snapshot cannot be saved. Modify only the
app-owned sidecar, never original audio or arbitrary source files.

## Acceptance criteria

- [x] First folder import creates a versioned metadata-only sidecar after publication.
- [x] Reimport/restart/moved-root import reuses unchanged metadata without walk/hash/decode; stable IDs and annotations survive.
- [x] Existing source imports are idempotent; sidecar metadata conflicts have an explicit revision policy and do not erase user edits.
- [x] Confirmed missing members are atomically pruned and absent from ready UI/MCP results.
- [x] Offline/inaccessible roots and failed/incomplete jobs preserve the prior snapshot.
- [x] Changed listed files alone reanalyze; new files require explicit Refresh; UI explains this behavior.
- [ ] Portable event-tag provenance survives sidecar reuse and model/version changes invalidate only affected enrichment.
- [x] Invalid schemas, oversized data, duplicates, traversal and symlink escape fail without DB mutation.
- [x] Read-only roots, concurrent writers and failed sidecar commit expose actionable recovery.
- [ ] File scopes, relink, source removal, backup/restore and watcher updates respect catalog membership and stale generations.

## Test scenarios

Instrument walk/hash/decode counts: first import versus warm reuse; 10k-entry
sidecar; relocated Unicode root; one deletion; one modified member; one unlisted
addition discovered only after Refresh. Inject offline drive, permission denied,
disk full, mid-write crash, cancellation and competing revisions. Verify DB and
sidecar recovery, source audio hashes unchanged, UI/MCP parity and rejected hostile
catalogs. Cache metadata reads are permitted; audio-byte reads on warm import are not.

## Review and completion

Record evidence and limitations in docs/reviews/SS-029.md. Mark acceptance
only after verification. Source audio bytes must never be changed. Schema or
identity changes require transactional migration and recovery evidence.

## Delivery limits

AI event-tag storage is not shipped yet: SS-016/017 must extend the versioned
sidecar contract and verify provenance on reuse. SS-022 must qualify populated
backup/restore with snapshot revisions, and SS-031 owns installed/platform tests.
Current measured profile tags, user annotations and complete clip revision
history are preserved. No AI recognition is claimed. Native read-only/conflict
recovery is implemented; source-side disk-full/power-loss fault injection remains
a release qualification item. Review evidence: docs/reviews/SS-029.md.
