# SS-027 review: macOS 26 native startup compatibility

## Findings

- The supplied crash report identifies `tao 0.35.3` in
  `platform_impl::macos::app_delegate::did_finish_launching`, with
  `panic_cannot_unwind` on macOS 26.6.2 ARM64.
- The fix is narrowly scoped to the vendored `tao` startup path: dispatch the
  initial event through the main GCD queue after `applicationDidFinishLaunching`
  returns.
- The workaround is reversible and documented in ticket SS-027. It does not
  alter SoundShelf catalog or media behavior.
- The packaged app also handles an absent `Contents/Resources` directory by
  using a fallback resource path, allowing optional media tools to be absent
  without failing the Tauri setup hook.

## Verification

- `npm test` passed: 2 tests.
- `node scripts/cargo.mjs test --workspace --locked` passed: 29 active tests;
  2 FFmpeg fixture tests remain intentionally ignored unless explicit fixture
  binaries are configured.
- `node scripts/desktop.mjs build --bundles app` passed and produced
  `target/release/bundle/macos/SoundShelf.app`.
- The rebuilt release executable remained alive when launched directly and did
  not reproduce the prior immediate `did_finish_launching` abort.
- The rebuilt macOS `.app` opened successfully as a native SoundShelf window;
  the UI reported the expected empty Library state.

## Residual risk

The macOS 26 workaround is local because the upstream `tao` fix is not yet
available in the locked dependency set. Re-test on an earlier supported macOS
release and replace the vendored dependency when upstream ships the fix.
