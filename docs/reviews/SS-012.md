# SS-012 Review: Clip recipes and selection

## Scope

Sample-exact non-destructive clip recipes and selection tools. Features include:
- Start/end and start+duration selection using source sample frames.
- Non-destructive saved clip variants stored in SQLite `clips` and `clip_revisions` tables with schema migration v4.
- Version-bound recipes: clips record source file content hash in `asset_version_id` and track incremental revisions (`revision`).
- Automated staleness detection: flags `is_stale = true` with detailed reason when source audio is replaced (content hash mismatch) or shortened past `end_frame`.
- Rebind action restoring freshness and logging historic revisions transactionally.
- Strict `[start_frame, end_frame)` exclusive end semantics with sample-exact rounding.
- High-precision decimal string representations for 64-bit frame counters across IPC and JSON serialization to prevent IEEE-754 precision loss.
- Clamping only with explicit feedback: audible and visual notification banner (`role="alert"`, `aria-live="polite"`) with "Fit to remaining audio" shortcut action.
- Waveform workstation controls: editable duration input, "Lock Duration" mode with synchronized bounds shifting, sample frame indicator, and Save Clip dialog.
- SoundInspector saved variants panel: lists saved clips, durations, frame boundaries, version badges (`v1`), stale warnings (`Source changed (stale)`), rebind, select, play, and delete actions.

## Acceptance Criteria Verified

- **Click start then enter 15 seconds**:
  - The waveform selection panel includes independent, synchronized numeric inputs for Start, Duration, and End.
  - Setting Start to an offset (e.g. 5.000s) and typing 15.000s into Duration automatically computes End to 20.000s and shifts sample frames accordingly.
  - Verified in `Waveform.test.tsx` (`supports Start + Duration entry (e.g. click start, enter 15s)`).

- **Exclusive end and exact rounding documented**:
  - Selection bounds represent `[start_frame, end_frame)` where `start_frame` is inclusive and `end_frame` is exclusive.
  - Frame length is exactly `end_frame - start_frame` samples.
  - Formulas and rounding rules documented and implemented using round-to-nearest integer sample frame with decimal string serialization.
  - Verified in `clip_scenarios.rs` (`fractional_seconds_and_exact_rounding`, `sample_rate_and_decimal_string_counters_44k_and_48k`) and `api.test.ts`.

- **Clamp only with explicit feedback**:
  - Neither start nor end silently truncates when out-of-bounds or zero-length input is entered.
  - An accessible alert banner (`role="alert"`, `aria-live="polite"`) appears explicitly detailing the adjustment (e.g., `"Duration exceeds file end; clamped to remaining audio: 4.000s."`).
  - An interactive button `"Fit to remaining audio"` allows the user to snap the selection to file boundary.
  - Verified in `Waveform.test.tsx` (`displays explicit clamp alert and provides "Fit to remaining audio" action`).

- **Recipes version-bound**:
  - Each clip persists `asset_version_id` (content hash of source audio at creation time) and `source_sample_rate_hz`.
  - Revisions are tracked in `clip_revisions` table. Concurrency conflicts on outdated revisions return error.
  - Verified in `clip_scenarios.rs` (`revision_concurrency_conflict_detected`, `v3_catalogs_gain_clips_table_transactionally`).

- **Source replacement flags stale recipes**:
  - When source audio content hash changes or source audio duration is shortened below `end_frame`, querying the clip flags `is_stale = true` with descriptive reason.
  - In SoundInspector, stale clips display a warning badge and a `"Rebind"` button.
  - Clicking Rebind updates the clip's `asset_version_id` to current source hash, clears staleness, and increments the revision.
  - Verified in `clip_scenarios.rs` (`source_replacement_flags_stale_recipes`, `source_shortened_flags_stale_recipes`, `rebind_clip_restores_freshness_and_creates_revision`) and `SoundInspector.test.tsx`.

- **Accessible inputs and handles**:
  - Selection inputs provide descriptive `aria-label` attributes (`Selection start in seconds`, `Selection duration in seconds`, `Selection end in seconds`).
  - Lock duration button uses `aria-pressed`.
  - Clamping feedback uses `role="alert"` and `aria-live="polite"`.
  - Keyboard navigation: arrow keys nudge selection bounds, spacebar triggers play, keyboard shortcuts supported.

## Core Feature Regression Fixes & UX Polish

Following user testing on live audio libraries, 7 regressions were resolved:

1. **Play button multi-trigger and startup latency**:
   - *Problem*: Rapid clicks enqueued concurrent `playback_play` IPC tasks. In debug mode, `Catalog::sound(id)` was an $O(N)$ table scan deserializing 2,000+ JSON waveforms (~90MB), holding the catalog lock for ~2.1s and causing delayed overlapping playback.
   - *Fix*: Added `isPlayPending` re-entry guard in `usePlayback.ts` and disabled play buttons during in-flight IPC. Optimized `Catalog::sound(id)` to direct $O(1)$ SQL primary-key lookup. Playback starts instantly with zero overlapping audio streams.

2. **Pause/Stop lag**:
   - *Problem*: Pause and stop waited for asynchronous IPC and periodic polling (120ms), feeling sluggish.
   - *Fix*: Applied immediate optimistic state transitions (`state: 'paused'`, `state: 'stopped'`) in `usePlayback.ts`, instantly updating transport icons and meter bars before backend round-trip completes.

3. **Audio selection dual-highlighting & race condition**:
   - *Problem*: `useAudioSearch.ts` included `results` in the `get_sound` selection effect dependencies. Frequent background polling updates triggered redundant `get_sound` requests that raced with manual clicks, momentarily highlighting multiple rows.
   - *Fix*: Removed `results` from the effect dependencies so selection queries only fire on `selectedId` changes. Added a tokenized selection version check in `App.tsx`.

4. **Redundant re-evaluation on scan retries**:
   - *Problem*: The background job polling loop computed signatures using full `Progress` objects (including incrementing `completed` and changing `current` filename), triggering search re-runs every 1.5s during library indexing.
   - *Fix*: Restricted polling refresh signatures to job status-level transitions (`queued` $\to$ `analyzing` $\to$ `complete`). Re-scans reuse cached profiles cleanly without UI thrashing or blank search results.

5. **Player smoothness**:
   - *Problem*: Catalog lock contention between background file scanner and playback control threads.
   - *Fix*: Replaced $O(N)$ full table scans in `reconcile()` and `sound()` with targeted index queries, eliminating catalog mutex lock starvation.

6. **Clip playback region boundaries**:
   - *Problem*: Playing a saved clip played the entire source file from the beginning.
   - *Fix*: Added `playback_play_clip(id, clip_id)` IPC command and backend `Player::play_clip(id, path, start_sec, duration_sec)` implementing ffmpeg `-ss` (seek) and `-t` (duration) bounded decoding. Saved clips now play strictly within their defined sample-frame boundaries.

7. **Folder sidebar filter**:
   - *Problem*: Selecting a source folder in the sidebar did not filter sounds to that folder.
   - *Root Cause*: `SearchQuery` in `search.rs` was marked `#[serde(deny_unknown_fields)]`. Tauri v2 IPC serializes incoming arguments to camelCase (`sourceIds`), which serde strictly rejected, causing deserialization to fall back to default empty filter.
   - *Fix*: Removed `deny_unknown_fields` and added `#[serde(alias = "sourceIds")]`, `#[serde(alias = "favoritesOnly")]`, `#[serde(alias = "minDuration")]`, and `#[serde(alias = "maxDuration")]`. Folder filtering functions accurately.

## Architectural & Security Notes

- **Non-destructive**: Source audio files are never modified, rewritten, or mutated.
- **Transactional Schema Migration**: Upgrades SQLite schema from version 3 to 4 with rollback safety and automatic index generation.
- **Integer Range Safety**: Audio frame indices stored as decimal strings over IPC prevent precision breakdown beyond $2^{53}-1$ on lengthy 96 kHz or 192 kHz recordings. Checked `u64` parsing in Rust ensures zero panics or overflows.
- **Staleness Tracking**: Rebinding creates audit trail revisions in `clip_revisions`.
