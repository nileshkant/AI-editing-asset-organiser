# SS-023 — security hardening and measured qualification

Status: partial qualification; reviewable hardening is implemented. This is not
an installed release certification. The threat boundaries, budgets and remaining
stress/physical gates are in `docs/SECURITY_QUALIFICATION.md`.

Findings fixed:
- Source media probe, preview, waveform and export now restrict FFmpeg inputs
  to file/pipe protocols and supported standalone audio demuxers, denying
  network URLs and HLS/concat disguised as audio. A loopback listener fixture
  observes no connection from direct HTTP and disguised playlists.
- Waveforms previously grew with file duration and cache counts allocated before
  checking payload length. Base buckets now adapt to a fixed cap; cache reads
  are bounded, dimensions/lengths are checked before allocation and samples must
  be finite. Algorithm v2 rebuilds older caches; temporary writes use create-new.
- Replaced yanked yoke-derive 0.8.3 with compatible 0.8.4. Other lock entries stay
  unchanged. CI now retains npm/RustSec audit reports and cancels stale PR runs.

Evidence on macOS aarch64, 2026-10-02:
- Actual optimized SQLite 100k search fixture: five queries 365/360/373/376/363 ms;
  separate instrumented run 363/494/430/361/353 ms, maximum RSS 337,903,616 bytes
  and peak memory footprint 294,290,224 bytes. One shared profile with one bucket
  makes this a small-profile baseline, not worst-case per-file waveform evidence.
  A concurrent compilation run took 713–1023 ms; load sensitivity is retained.
- Real one-file cold import: 190 ms, one walk/two hashes/one decode. Warm metadata
  import: 11 ms, zero walks/hashes/decodes. Separate SS-029 10k fixture retains
  zero-IO assertions and now passes Windows/macOS/Linux CI.
- Full configured workspace fixtures: 190 passed, none failed/ignored. Corpus
  cases cover parser bytes/queries, forged cache allocations, non-finite values,
  oversized cache, adaptive resolution and network/playlist denial, plus existing
  source catalog locks/CAS/pruning and scoped MCP/export/timeout tests.
- Native command compilation passed. Frontend remains the SS-022 tested 131-test
  build; no UI changes here.
- npm audit: zero advisories. RustSec cargo-audit 0.22.2: zero vulnerability entries,
  six unmaintained dependency warnings and one unsound warning in glib 0.18.5.
  These warnings are not an all-clear. The yanked warning is gone after the patch.

Linux GTK unsoundness RUSTSEC-2024-0429 is tracked in SS-034. It is in the
GTK/Tauri/muda dependency chain; upgrading to glib >=0.20 is not a compatible
one-line change for GTK3. Linux release support remains blocked. Unmaintained
proc-macro-error/unic warnings need a dependency maintenance decision. No
warning was suppressed. Audit tool installation used the compatible installed
macOS 26 SDK after the default SDK 27 linker failed; no SDK files were modified.

Limits: deterministic corpus testing is not sustained coverage-guided fuzzing;
physical audio, installed MCP clients, screen reader/contrast, long sessions,
worst-case profile memory, OS fault injection and signed packages remain gates.
No private source audio or catalog was tested. Windows fixture and backup fixes
stay in their owning SS-029/022 PRs; all four affected ticket PR CI runs are green.

## Post-merge search memory finding (schema 9)

PR #25 is merged. Remaining acceptance is release qualification; it is not
missing implementation. Review identified that both desktop and MCP search
loaded every selected waveform and only discarded it when returning results.

The follow-up changes both search paths to use compact derived metadata.
Authoritative full profiles still serve playback/inspection/sidecar output.
SQLite triggers synchronize the cache on analysis insert/update/delete. Schema 9
creates/backfills it transactionally after saving a pre-migration backup. Restore
rejects an inconsistent search cache before creating rollback or changing live data.
Scope filtering still runs in SQL before decoding profiles; desktop source counts
above the MCP grant limit are read in bounded groups.

Actual optimized macOS aarch64 measurements, 2026-10-02, generated fixtures:
- 100k records sharing a 3,200-bucket profile: 423/387/426/432/588 ms; peak RSS
  400,343,040 bytes. Shared profiles test per-row amplification, not per-file disk use.
- 10k records with distinct 3,200-bucket profiles: 145/104/121/310/88 ms; peak RSS
  40,812,544 bytes; fixture database 333,754,368 bytes.
- Same 10k distinct fixture using the previous full-profile search path:
  2075/1862/1839/2058/1432 ms; peak RSS 370,245,632 bytes.
- Raw reports: `evidence/SS-023-search-100k-compact.txt`,
  `evidence/SS-023-search-10k-distinct-compact.txt`, and
  `evidence/SS-023-search-10k-distinct-reference.txt`.

Build the fixture with `node scripts/cargo.mjs test -p soundshelf-core --test
qualification --release --locked catalog_search_100k_records --no-run`; run the
printed test executable directly under `/usr/bin/time -l` to exclude compiler
memory. Set `CREATIVESHELF_BENCHMARK_BUCKETS=3200`; add
`CREATIVESHELF_BENCHMARK_RECORDS=10000 CREATIVESHELF_BENCHMARK_UNIQUE=1`
for distinct profiles, and `CREATIVESHELF_BENCHMARK_FULL_PROFILES=1` for the old
path reference. Each fixture drops its temporary catalog after measurement.
The environment had concurrent local application/build activity. Five runs are
comparative evidence, not a p95 or all-platform certification.

Regression checks cover retained full waveforms, current semantic tags after
profile updates, cache deletion, populated v8 migration/backup, failed migration
rollback, and rejection of altered derived metadata on restore. No user catalog
or source audio was opened or changed. Sustained fuzzing, two-hour mixed sessions,
signed installers and installed physical audio/client/accessibility gates remain.

Validation: `SOUNDSHELF_FFMPEG=/opt/homebrew/bin/ffmpeg SOUNDSHELF_FFPROBE=/opt/homebrew/bin/ffprobe node scripts/cargo.mjs test --workspace --locked -- --include-ignored` passed 194 tests, zero failed or ignored, including real generated media and MCP shutdown fixtures. The initial restricted run could not bind its loopback fixture; the rerun with loopback permission passed. No production app was restarted.
