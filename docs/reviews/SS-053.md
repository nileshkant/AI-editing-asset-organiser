## Behavior and evidence

- **R1, R5**: The SS-052 worker uses the SS-050 provider adapter with the v2
  visual response schema. It verifies the selected original before using a
  cached preview or result and rechecks the original after a successful
  provider response. The asset evidence records the exact input digest,
  provider and configuration revision, model and reported revision when
  available, preprocessor and response schema, coverage, time and uncertainty.
  Tests cover production preview dimensions and a same-stat replacement in flight.
- **R2, R3, R4, R6**: The parser accepts only eight visual categories and a
  bounded caption. Each category retains its own deduplicated labels. Model
  output remains suggested evidence with unavailable confidence. User
  captions and tags are stored separately. The parser rejects unknown
  fields, unsupported categories and oversized or empty certain answers.
  Uncertain responses and responses lacking a caption or tags display as
  partial. Captions and labels are plain text. The prompt forbids unsupported
  identity, generator, rights and hidden-part claims. A model may still
  hallucinate and its predictions require human review.
- **R7**: Paid result, attachment and evidence are written inside the
  existing consent, content and job transaction. Existing image triggers mark
  the search index and folder snapshot dirty. Portable transfer, sidecar and
  database backup all keep the typed evidence. The SS-058 search layer
  already supports opt-in suggested tags and captions and resolves explicit
  aliases at query time.
- **R8**: The inspector shows the latest current evidence, provenance and
  per-image job status. Retry uses the existing queue and asks for explicit
  acceptance before retrying an unknown billing outcome. The creator can copy
  a suggestion into a separate editable caption and save or undo it through
  the annotation service.
- **R9 / A2**: The held-out CLI uses the production thumbnail renderer, PNG
  preparation and structured adapter. The local Gemma 3 run completed and
  missed five quality thresholds. Thresholds remain as registered in SS-050.

## Migration and recovery

Schema v20 adds no table or column. It permits an optional structured
suggestion field in the existing image evidence JSON. A pre-v20 backup is
created by the existing migration path. Pending v1 work is cancelled and
in-flight reservations become unknown outcomes. Completed v1 cached results
are retained locally and the v2 schema starts with its own cache keys.
Nothing is automatically re-sent. Portable records carry evidence, while
consent, reservations and cached provider answers stay machine-local. A
catalog may hold up to 128 evidence records per image inside the existing
record byte limit. An upgrade or failed publication leaves user annotations
untouched.

The sidecar round trip also tests a member whose stats changed. Its evidence
is marked stale immediately so a pending image can load without treating that
evidence as current.

## Developing the qualification fix

The version 2 development run marked nine of fourteen images uncertain, even
when its captions described visible shapes or colors. The parser discarded all
tags for these images. The version 3 prompt asks for one visible feature per
label, including foreground and background features. It reserves the global
uncertainty flag for images with no reliable visible feature. Older jobs cannot
run with the new prompt, and the evidence and cache retain the prompt version.

The development-only Gemma run used the original 14 development images and
their labels. Tag recall went from 20.0% to 77.1%. Caption fact coverage went
from 63.6% to 90.9%, and uncertainty went from nine images to zero. Tag
precision was 80.0%. The original embedding model still returned an unrelated
result on the development queries.

Re-embedding the same development captions with Qwen3 Embedding 0.6B and an
asset-search instruction produced 85.0% recall@5, 0.913 MRR and zero unrelated
results. The document vectors still use plain insight text, and the embedding
space identifies the new query recipe. Both out-of-domain cases are shared by
the original development and held-out retrieval reports. The frozen thresholds,
positive-label split, and development cutoff rule stay as registered.
[Qwen3 Embedding model card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)

The full v3 run at `8e12e11` paired Gemma 3 4B with Qwen3 Embedding 0.6B
(Ollama manifest SHA-256
`d84267e5df12e19a8be357ab23b88966d61137226724f399707dee270cebccd3`).
It completed all 41 requests with zero failures. Held-out tag recall was

85.7% tag recall, 86.4% caption coverage and 95.0% retrieval recall@5.
Development p95 was 14.8 s and both unrelated queries were rejected. Those
results determined the model and prompt for the full run.
