Test files: core unit `crates/core/src/image_preview.rs` (U), real-worker integration
`crates/core/tests/image_preview.rs` (I), gated native AppState

- **R1 tiers / versioned keys.** `preview` worker mode reuses the SS-042
  `decode_display` pipeline (orientation once, ICC → sRGB, straight alpha). Tiers:
  small/medium/large 128/256/512 from one decode, inspect ≤ 2,048, 512² 1:1 tiles.
  Keys: digest + tier/tile inside a namespace hashed from preview version, analyzer
  and `srgb` policy. I: `thumbnail_tiers_apply_orientation_and_color_once…` checks
  EXIF 6 quadrant maps for every tier, exact sizes (85×128, 171×256, 341×512,
  400×600), Adobe RGB → sRGB `[146,62,23]` ±6, and one decode for three tiers.
  I: `inspection_and_full_resolution_tiles…` checks 4096×1024 → 2048×512 inspect,
  tile (7,1) mapping to source (3584,512), and out-of-grid tiles rejected.
- **R2 atomic, validated, coalesced, metadata-safe.** Temp + fsync + rename; records
  are self-verifying (header fields, BLAKE3, PNG IHDR/JPEG SOF dimensions). The
  parent validates the worker batch (magic, digest, analyzer, dimensions, MIME,
  hashes, exact byte accounting). U: corruption/truncation/foreign-record repair,
  disk-full partial write (`StorageFull` injected mid-write → no record and no
  temp). I: 8 concurrent requests → exactly one decode; restart with a bogus
  worker still serves hits; corrupted record regenerated (`repaired = 1`).
  Cache code never writes catalog rows; originals are byte-compared after each test.
- **R3 asset-ID/version service.** Commands take ID, digest, tier and tile only.
  No URI scheme; CSP adds `blob:` only. Authorization under the catalog lock,
  containment at open, and a re-check before serving. I: traversal-shaped IDs →
  `INVALID_ARGUMENT`, unknown ID → `NOT_FOUND`, wrong ID/version pair →
  `STALE_VERSION`, removed source → `NOT_FOUND` with cache records still present,
  swapped-in escaping symlink → `ORIGINAL_UNAVAILABLE` (Unix). R: envelope rejects
  other asset/version/tier/tile, non-image MIME, inconsistent offline flags,
  oversize headers and bad magic.
- **R4 quota / LRU / concurrency / cancellation / owned cleanup.** 512 MiB default
  (64 MiB–16 GiB), pinned reads never evicted, 2 preview slots, 256 outstanding
  (8 inspect), 20 s deadline. U: LRU respects quota and pins, clear defers pinned
  records, quota bounds, outstanding/inspect bounds, unique request IDs, restart
  removes only `tmp/<uuid>.part` and our superseded namespaces (a foreign
  `notes.part` and `v1-not-ours` survive). I: cancel kills an active decode in
  < 3 s with no record written; cancelling one of two coalesced requesters lets the
  survivor complete. R: unmount/prop change cancels in flight and revokes owned URLs.
- **R5 offline vs cached.** `original_available` / `offline_reference` in every
  response. I: offline source serves the cached small tier labelled offline, but
  inspect → `ORIGINAL_UNAVAILABLE` and no decode. R/B: "Offline reference ·
  original unavailable, export disabled" caption; no export affordance exists.
- **R6 stale fencing / invalidation.** I: same-path replacement keeps the ID, old
  version → `STALE_VERSION`, new version `NOT_READY` until published, then new
  pixels. Prune removes exactly the replaced digest's 3 records. Identical bytes at
  another path reuse pixels under their own ID. R: a late v1 reply after a v2
  prop change is ignored without creating a URL. Restore re-prunes and reloads quota.
- **R7 actual alpha.** I: hidden green under zero alpha does not bleed into the red
  edge after a 1024→128 downscale; 50% alpha stays 128 ±1; transparent pixels are
  `[0,0,0,0]`; tiles keep exact straight-alpha source pixels. Mutation check:
  forcing the straight-alpha path makes this test fail. Checkerboard is a CSS
  class only (R/B assert the class).
- **R8 size/rebuild controls, diagnostics.** Settings → Audio & recovery card:
  quota select, refresh, confirmed clear, and counts only. R: hidden when disabled
  and empty; quota persists via `set_image_preview_cache_quota`; clear requires
  confirmation. N: status contains no source root or asset ID. U: the quota is
  stored in its own key, invalid values fall back, and `Preferences` stays readable.

## SS-040 contract ceiling (found during review)

`MAX_PREVIEW_DIMENSION = 2048` and `MAX_PREVIEW_BYTES = 4 MiB` were frozen in SS-040:
"a transport must use a smaller tier when … overhead would exceed its payload
cap". The first implementation allowed raw-sized PNGs (a 2048² alpha PNG could
reach ~16 MiB). Fixed by bounding every output at 4 MiB. Inspect steps down
2048 → 1536 → 1024 → 768 → 512, and the parent accepts only those exact steps.
I: a 1100² incompressible transparent image yields a 768×768 PNG ≤ 4 MiB with alpha.

## Other review findings fixed

- **Duplicate decode race.** A request could miss the cache just before a leader
  published and dropped its flight, then decode again. New leaders now re-check
  all job outputs in the cache (uncounted) before spawning a worker.
- **Quota startup race.** The background refresh could apply a stale stored quota
  after a user change. Both paths now apply the quota under the catalog lock. The
  directory index loads before the lock is taken.
- **Transient memory.** Inspect cache hits are read whole; a separate 8-request
  inspect cap plus the 4 MiB ceiling bounds transient bytes to ≈ 8 × 4 MiB +
  248 × ~1 MiB.
- **Preferences compatibility.** Adding the quota to `Preferences`
  (`deny_unknown_fields`) would make an older binary fail at startup on this
  catalog, so it uses a separate `app_settings` key.
- **Test fixture isolation.** The new settings card fetches status on mount, which
  broke existing tests asserting no IPC. Following the existing pattern for
  `RecoverySettings`/`McpSettings`, `FileImport.test.tsx` mocks the card. Assertions
  are unchanged; the card itself uses the established `call()` idiom.
- **Layout.** Screenshots showed the offline caption wrapping mid-word inside the
  4rem frame, and sub-MiB sizes showing as "0 MiB". The caption now sits below a
  fixed frame; small sizes show in KiB. Both were re-inspected at 100% and 200%.
- **CI coverage.** The gated native CI step filtered on `image_import`, which would
  skip the new native test. It now runs `image_`.
- **Windows CI: refresh thread outlived shutdown.** The first PR run failed on Windows
  only: the native test's cleanup hit error 32 (file in use). The startup/restore
  prune thread was detached and held a strong catalog `Arc`, which could keep the
  SQLite file open after `AppState::shutdown`. macOS allows deleting open files, so it
  never showed locally. The thread now holds a `Weak` catalog reference, its handle is
  retained, and `shutdown()` joins it.
- **Native test interference.** Running both gated native tests in one process exposed
  contention for SS-042's process-wide single analysis slot. The concurrent import
  item failed BUSY, an intermittent failure of the SS-043 test. Production has one
  import engine per process, and previews use separate slots. Both tests now share
  `service::NATIVE_IMAGE_TESTS`; 10/10 consecutive local runs passed.
- **Windows CI, second run.** The same cleanup error remained because the test itself
  kept a `PreviewService` clone, which holds the catalog `Arc`, alive past
  `drop(state)`. The test now releases it before deleting its directory.

## Schema, persistence and recovery (A5)

No schema change and no new catalog table or column. The only durable addition is
the `app_settings` row `image_preview_cache` (`{"quota_bytes":n}`). Full SQLite
backup/restore carries it, restore reapplies it, older binaries ignore it, and
invalid values fall back to the default. Portable JSON and source snapshots are
unaffected: a machine cache-size preference, not asset metadata. The preview cache
itself is disposable derived data outside the database. It is excluded from backup,
snapshot and portable formats, rebuilt on demand, and pruned to current digests at
startup and after restore. Deleting a source/image leaves unreachable records until
prune/LRU; they are never served because each request is re-authorized. Optional AI,
consent, model, export, MCP and editable artifacts: inapplicable, none are added.

## Remaining limits and handoff

PR: https://github.com/nileshkant/AI-editing-asset-organiser/pull/46 (targets main).
CI results are recorded on the PR for its exact head; no merge is authorized here.


Verified locally on macOS arm64 only. CI must establish Windows/Linux behavior on
the pushed head (rename-over-existing, owned-temp cleanup and kill/reap on those
runners). Not verified: installed builds, physical displays/high-DPI rendering in the
native webview, removable-drive or network-mount behavior, and real disk-full
conditions (injected only). `original_available` is the catalog state; a hit does
not probe the file. Kernel-level stalls on broken mounts are not killable (SS-042
limitation). Tiles decode the full image per tile; SS-045 should request visible
tiles only and may need a batched tile job if measured panning is too slow.

**Handoff to SS-045** (do not implement here): call `imagePreview(requestId, assetId,
version, tier, tile?)` from `src/api.ts` or reuse `ImagePreview`. Handle every
`ImagePreviewError`, cancel on scroll-out, revoke URLs, and use `meta.width/height`
and `source_width/height` for fit/100%. Inspect may arrive below 2,048 when the
4 MiB ceiling forces a smaller step. `tile` gives 512² 1:1 cells for zoom/pan.
Thumbnails are bounded at 128/256/512; the gallery picks a tier from its rendered
size × devicePixelRatio. `image_preview_cache_status` exposes counts for rebuild
UX. `importedImages` (core `list_images`) remains the paginated metadata source.
