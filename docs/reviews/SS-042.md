## Memory and resource evidence

Local macOS arm64 debug, actual worker, maximum admitted 4096² pixels:

- RGBA8: allocator high-water **134,357,671 bytes**; independent `/usr/bin/time -l`
  maximum RSS **142,491,648 bytes**, peak footprint **137,036,352 bytes**; standalone
  sample elapsed **2.05 s**.
- Rotated RGBA16: allocator high-water **201,597,641 bytes**; maximum RSS
  **276,987,904 bytes**, footprint **271,532,704 bytes**; standalone sample
  elapsed **4.60 s**.

These are fixture measurements, not a universal process-RSS or speed guarantee.
The enforced allocation budget excludes stack/mappings/allocator overhead.
OS filesystem calls on a broken mount can stall in the kernel; hash checkpoints
bound computation between reads rather than promise interruptibility of those
kernel calls. The independently supervised decoder and blocked child reads are
killable. Filesystem and SQLite commits are not atomic against arbitrary external
writers: reverify immediately before publication; later external edits need refresh.
No stat-only equivalence or impossible filesystem lock guarantee is claimed.

## Review findings and changes

1. Library resource limits are not uniformly strict: put all codecs/color work
   in a separately supervised binary with an enforced GlobalAlloc budget.
2. Reallocation can temporarily hold old and new buffers: explicitly allocate/
   count both, copy then free; peak accounting includes the overlap.
3. Display quantization can hide 16-bit partial alpha: measure original samples
   first, then convert; preserve alpha through ICC transforms.
4. A successful header/first frame is insufficient: require full decode, canonical
   pixel hashes and reject animation explicitly before decoding.
5. Prevent bypassing final byte verification: analyzed and verified publications
   use distinct consumed types. Generation/content are checked again at commit.
6. Metadata text and ICC can expand beyond compressed size: preflight expands
   bounded PNG metadata before codec construction and validates EXIF/ICC bounds.
7. Fixtures use real codecs and native child processes; no mocked decoder can
   satisfy these pixel/resource assertions. Three tiny independent fixtures use
   Pillow 11.3.0/libwebp 1.5.0 only during regeneration, never in the app runtime.
