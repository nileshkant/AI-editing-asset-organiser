# SS-010: Native audio playback review

## Overview

SS-010 delivers SoundShelf's native audio playback engine. It establishes pure offline, low-latency, hardware-accelerated playback for WAV, MP3, and all media formats supported by FFmpeg, bypassing Web Audio in the frontend entirely. The engine guarantees real-time safety in CPAL audio callback threads, lock-free SPSC buffer streaming, bounded memory consumption, deterministic natural-end detection, graceful underrun silence, rapid seek stability, and file safety (zero database modifications or file deletions on decode failures).

## Key Implementation Components

1. **Real-time Safe Audio Callback (`crates/core/src/playback.rs`)**:
   - Zero heap allocations (`alloc::alloc` / `realloc`) during audio rendering.
   - Zero blocking mutex acquisitions in the CPAL audio callback path: utilizes lock-free single-producer single-consumer ring buffers (`rtrb::Consumer<f32>`).
   - Atomic state sharing (`AtomicU32` for bit-casted IEEE 754 float volume and live peak meter, `AtomicU64` for played frames and underrun counters, `AtomicBool` for playback control and EOF signaling).
   - Clean silence output on buffer underrun without clicks, audio glitches, or priority inversions.

2. **Streaming FFmpeg Subprocess Decoder**:
   - Spawns background decoder streaming uncompressed `f32le` PCM over stdout pipe with `-ss <seek_offset>`, resampled to device sample rate and channels.
   - Bounded memory footprint (~384 KB ring buffer regardless of the audio file duration or format). When full, the decoder thread yields and sleeps, consuming zero extra RAM.
   - Child process lifecycle is safely owned: cancellation signals, kills, and reaps the child process immediately, joining background threads without leaving zombie processes.

3. **Audio Sinks & Headless Verification**:
   - `OutputSink::Cpal`: Native hardware device output via CPAL with error callbacks propagating stream errors to status.
   - `OutputSink::Loopback`: Deterministic loopback sink (`LoopbackSink::step(frames)`) capturing exact PCM frames for automated testing without requiring physical audio hardware in CI.

4. **Tauri IPC Transport API (`src-tauri/src/main.rs`, `service.rs`)**:
   - Exposes `playback_play`, `playback_pause`, `playback_resume`, `playback_stop`, `playback_seek`, `playback_set_volume`, and `playback_status`.
   - Lifecycle managed cleanly on app launch and graceful shutdown.

5. **Transport User Interface (`src/App.tsx`, `src/styles.css`)**:
   - Persistent transport footer docked at the bottom of the application.
   - Play/Pause toggle, Stop, Scrub bar with current position and total duration display.
   - Post-gain live peak meter bar.
   - Volume slider with Mute/Unmute toggle.
   - Spacebar global keyboard shortcut for transport toggling.
   - In-row play/pause button on every sound card in the library list.
   - Transport state persists across searching and folder switching.
