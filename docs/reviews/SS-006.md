# SS-006: Folder relink and availability review

## Scope

Implemented and verified root relinking, volume availability lifecycle, source generation protections against stale workers, missing sound absenteeism across search and inspection queries, atomic rollback on relink failure, and partial scan safety.

## Changes

1. **Catalog Availability & Readiness Contract (`crates/core/src/catalog.rs`)**:
   - Added `Catalog::ready_sound(&self, id: &str) -> Result<Sound>`: ensures a sound is returned only if `status == "ready"` and its parent source is online (`available == true`). Rejects missing sounds with `"Sound is not ready"` and offline sources with `"Source is offline"`.
   - Updated `Catalog::resolve(&self, id: &str) -> Result<PathBuf>` to delegate readiness checks to `ready_sound`.
   - Guarded `Catalog::annotate`: disallows updating annotations on missing sounds (`"Cannot annotate missing sound"`) or offline sources (`"Cannot annotate sound in offline source"`).

2. **Desktop Backend API (`src-tauri/src/main.rs`)**:
   - Updated `get_sound` IPC command to use `ready_sound`, guaranteeing that neither the UI nor future MCP clients can query details for missing sounds or sounds from offline sources.
   - Preserved `search_sounds` filtering to exclusively search online sources with `status == "ready"`.

3. **Frontend Absenteeism & Inspector Deselection (`src/App.tsx`)**:
   - Added automatic active inspector cleanup on search/library refresh: checks the currently selected sound using `get_sound`; if the sound was deleted on disk and reconciled as missing, or its source was marked offline, the inspector selection immediately dismisses.

4. **Deterministic Test Suite (`crates/core/tests/relink_and_availability.rs`)**:
   - `missing_sounds_absent_from_search_and_queries`: verifies missing sounds and offline source sounds are rejected by `ready_sound`, `resolve`, and `annotate`, and are omitted from all search permutations (empty query, text, tags, favorites, duration range, explicit source filter).
   - `volume_unplug_and_restoration_lifecycle`: verifies unplugged mount sets `available = false` while keeping sounds intact as `ready` (not deleted, not marked missing), blocks resolve/search, and remounting restores availability without re-analysis.
   - `reconciliation_marks_deleted_file_missing_and_resurrection_reuses_profile`: verifies deleted file is marked `status = 'missing'`, absent from search/inspection, and restoring the file resurrects it to `status = 'ready'` reusing its profile from the `analyses` cache.
   - `relink_reuses_identity_with_zero_decode_jobs`: verifies moved folder relink succeeds, increments generation, reuses cached profile, preserves user annotations, and resolves to new paths.
   - `wrong_relink_destination_is_atomic`: verifies mismatching content or non-folder relink target fails atomically without modifying source root or generation.
   - `one_changed_file_alone_reanalyzed`: verifies modifying 1 file in a multi-file source re-analyzes only the changed file while reusing unchanged files and preserving user annotations.
   - `partial_scan_never_mass_deletes`: verifies incomplete scans (`complete = false`) never mark unseen files missing.
   - `stale_worker_scan_rejection`: verifies source generation increments block stale worker register, publish, and reconcile attempts.
   - `overlapping_roots_rejected_at_add_and_relink`: verifies duplicate roots, nested roots, and overlapping relink destinations are rejected.
   - `paths_and_symlink_security`: verifies relative path traversal rejection and Unix symlink escape rejection.
