## Requirement coverage

Test files:
- **C** (core, real SQLite with FTS5): `crates/core/src/image_search.rs` tests.
- **M** (migrations and legacy fixtures): same file, plus
  `crates/core/tests/maintenance_scenarios.rs` and the other legacy-fixture
  suites through `crates/core/tests/common/mod.rs`.
- **R** (renderer): `src/ImageSearch.test.tsx`, `src/ImageGallery.test.tsx`.

- **R1 query, filter and result contracts.** `ImageQuery` (version 1, unknown
  fields rejected) covers kind, text and text fields, source ids, confirmed and
  excluded tags with a tag state, favorites, rating range and "rated",
  width/height ranges, orientation, alpha channel, measured transparency, format,
  technical/availability/enrichment state, ready-only, review state, provenance
  (where tags came from), added-date range and sort. `ImageSearchPage` returns
  items, a per-hit explanation (tier and matching fields), the interpretation and
  optional facets. Contradictions (min > max, a tag both required and excluded)
  are `INVALID_ARGUMENT`, never silently relaxed.
  - C: *contract_rejects_unknown_fields_versions_and_reserved_fields*.
- **R2 text fields and token semantics.** Default fields are file name, confirmed
  tags, caption and notes; suggested tags are opt-in. Terms match whole tokens,
  `"quoted phrases"` match in order inside one field (a separator stops a phrase
  spanning two tags), `-word` excludes, `word*` is a prefix. Text is NFC,
  case- and accent-folded; CJK characters are single tokens so substrings match.
  Input that cannot be searched is listed in `ignored`, not dropped silently.
  - C: *text_matches_whole_tokens_phrases_prefixes_and_exclusions*,
    *unicode_is_normalized_case_and_accent_folded_and_cjk_is_searchable*.
- **R3 hard predicates and unknowns.** Dimensions, transparency, alpha, rating,
  availability, source scope and exclusions are SQL predicates on stored
  columns. Unknown width, alpha, transparency or rating never satisfies a filter
  and is never treated as zero, false or approved.
  - C: *hard_filters_never_treat_unknown_as_zero_false_or_approved*.
- **R4 ranking, pagination, facets.** Relevance is a fixed tier (0 exact tag,
  1 tag token, 2 caption, 3 file name, 4 notes, 5 other field), then file name
  keys, then id. Other sorts put unknown values last and break ties the same way.
  Pages are offset windows (limit ≤ the gallery maximum) over the live result:
  an edit between windows gives a new consistent order, and the gallery refreshes
  its windows. Facets are counted after authorization, over the same filtered
  set, in one pass.
  - C: *windows_are_stable_and_stitch_without_gaps*,
    *authorization_bounds_results_counts_facets_and_guidance*.
- **R5 suggested versus confirmed, transactional indexing.** Tags are indexed
  with their state; filters default to confirmed and can ask for suggested or
  either. Evidence counts only for the current content hash: accepted or edited
  is confirmed, suggested stays suggested, rejected and stale are ignored.
  Aliases resolve to their canonical tag and the interpretation says so.
  Every image, version and path change queues the asset in the writer's
  transaction; the next search rebuilds those documents first.
  - C: *suggested_and_confirmed_tags_stay_distinct_and_aliases_resolve*,
    *edits_deletes_and_moves_are_visible_to_the_next_search*.
- **R6 UI and saved searches.** Search box (300 ms debounce), Filters panel
  offering only available fields, sort menu, result line describing the
  interpretation, per-tile explanation (accessible name and tooltip), Clear all,
  facet counts, no-match guidance (per-clause counts, "N images match your words
  but not the other filters", spelling suggestions verified inside the user's
  scope) and saved searches with explicit Replace on a name conflict. Searches
  saved by a newer version are listed but report that they cannot be opened.
  Only structural filters and sort are remembered in local storage; typed text
  and tag names are never stored.
  - R: all five tests in `src/ImageSearch.test.tsx`.
  - C: *no_match_guidance_reports_counts_and_text_only_matches*,
    *saved_searches_round_trip_portably_and_stay_out_of_source_snapshots*.
- **R7 indexes, plans and measured latency.** No search reads annotation JSON,
  decodes or hashes a file. Plans are asserted on the exact compiled statements:
  text is driven by the FTS5 match set with primary-key joins, tag filters probe
  the tag key index, and neither scans the asset or document tables.
  - C: *large_libraries_search_through_indexes_within_budget* (numbers below).
- **R8 audio unchanged.** `crates/core/src/search.rs` and the audio commands are
  untouched; image search is its own module and contract. The audio search
  suites pass unchanged.

## Failure and boundary scenarios

- **T1** query matrix: exact, phrase, exclusion, prefix and misspelling
  (suggestions), Unicode, aliases, unknowns, numeric boundaries, and no AI model
  configured (search is fully offline; nothing calls a provider). Tests listed
  under R2, R3, R5.
- **T2** authorization and ready selection: a caller limited to some sources gets
  the same totals, facets and guidance as if the other sources did not exist,
  and naming an unauthorized source narrows the scope to nothing rather than
  revealing whether it exists. Missing, failed, pending and
  offline images are excluded by `ready_only`.
  *authorization_bounds_results_counts_facets_and_guidance*,
  *ready_selection_excludes_missing_failed_pending_and_offline_images*.
- **T3** ordering, immediate updates, large libraries: see R4, R5, R7.
- **T4** shared contract:
  - Authorization: T2.
  - Concurrency: the index is rebuilt inside a savepoint on the searching
    connection before reading; the per-connection result cache is reused only
    when `total_changes()` and `PRAGMA data_version` are unchanged, so a write
    from this or another connection invalidates it.
  - Cancellation: a search is one bounded synchronous call (limits on terms,
    phrase count, tag count and window size); there is no long job to cancel.
  - Persistence and recovery: see "Schema v16".
  - Resources: input limits return `LIMIT_EXCEEDED`; facet tag lists are capped.
  - Accessibility: the search box, filter controls and saved-search controls are
    labelled; status messages use `role="status"`; tiles carry the explanation in
    their accessible name.
- **T5** audio and media: no audio code path changed, and search never opens
  media, so original file hashes cannot change. Full workspace suites pass (see
  commands).

## Schema v16 and recovery

New tables: `image_search_docs`, `image_search_tags`, `image_search_fts` (FTS5
`unicode61 remove_diacritics 2`), `image_search_dirty`, and
`saved_image_searches`, plus six triggers that only queue asset ids. All search
tables are classified **R** (rebuildable) in
`mixed_catalog::persistence_inventory`, including the FTS5 shadow tables;
`saved_image_searches` is **P** (portable) except the derived `name_key`.

The v15 → v16 upgrade runs in the existing transactional path after the
pre-upgrade backup, creates the tables, queues every existing image and builds
the index before commit. A failure rolls back and leaves a usable v15 catalog
with its backup. If the index were ever lost, `refresh_image_search_index`
rebuilds it from catalog data.
- M: *genuine_v15_upgrade_indexes_existing_images_with_a_backup*,
  *v16_failure_rolls_back_and_keeps_the_v15_catalog_usable*.

Saved searches are in portable catalog v2 (`saved_image_searches`, omitted when
empty, rejected in a v1 file) and are validated and imported in the same
transaction as the rest of the catalog. Per-source snapshots never contain them
and reject a snapshot that does.

## Reserved fields

`ocr`, `generation` and `usage_notes` are part of the `TextField` contract but
return `UNSUPPORTED_FIELD`; `image_search_capabilities` reports them unavailable
with the owning ticket (SS-057, SS-055, SS-056) and the UI does not offer them.
Those tickets add a column to the FTS document and flip the capability; the
query contract does not change.

## Measurements

`cargo test --release --locked -p soundshelf-core --lib large_libraries -- --nocapture`,
Linux container, rustc 1.97.0, rusqlite 0.38.0 (bundled SQLite, libsqlite3-sys
0.36.0). Synthetic catalogs with tags, captions, notes, mixed dimensions and
ratings. First window is offset 0 with facets; the second window is the middle
of the result without facets (served from the result cache).

| Query | 10K first | 10K middle | 100K first | 100K middle |
|---|---|---|---|---|
| Rare note term | 7.5 ms | 0.15 ms | 44.7 ms | 0.20 ms |
| Common tag term (80%) | 85.5 ms | 3.5 ms | 1.07 s | 41.7 ms |
| CJK substring (100%) | 97.0 ms | 6.0 ms | 1.23 s | 51.2 ms |
| Phrase + exclusion | 3.6 ms | 0.13 ms | 28.8 ms | 0.29 ms |
| Prefix | 3.8 ms | 0.12 ms | 35.2 ms | 0.17 ms |
| Exact tag filter | 10.9 ms | 0.13 ms | 123 ms | 0.25 ms |
| Rating ≥ 4, landscape, width ≥ 1000 | 12.7 ms | 0.13 ms | 159 ms | 0.19 ms |
| Rating sort, all images | 78.8 ms | 1.2 ms | 1.21 s | 1.9 ms |
| No match with guidance | 12.3 ms | 0.26 ms | 133 ms | 1.6 ms |

Index build from scratch: 0.52 s (10K), 6.1 s (100K). Search after editing one
image (re-indexes one document): 2.1 ms (10K), 2.3 ms (100K).

The slow cases at 100K are the ones that match most of the library and sort and
facet all of it; selective queries stay under 160 ms. The gallery does not ask
for facets with every window (they load when the filter panel needs them), and
an unfiltered name-sorted view still uses the SS-045 gallery index. Before the
CTE driver change, a common word took 21 s at 10K because SQLite probed the
document index once per FTS hit; the plan assertions guard against that.
Debug builds (CI) run the 10K case with generous ceilings.

## Review findings and fixes

- Quadratic plan for common words (above): fixed by materializing the FTS match
  set and forcing it as the outer loop.
- Broad first windows recomputed the whole ordered result for each window: fixed
  with the per-connection ordered-id cache and single-pass facets.
- Provenance first counted stale and rejected evidence: now only current,
  non-rejected evidence counts.
- Saved-search replace kept the old spelling of the name: it now takes the new
  one.
- Legacy test fixtures that strip image storage now also drop the v16 objects.

## Limits

- Provenance filters use recorded evidence only; there is no generation history
  yet (SS-055).
- "Needs review" means the image has pending suggestions; SS-054 may refine it.
- 100K figures are measured in a release build only; CI runs 10K in debug.
- Pages are offset windows over a live result, not cursors; an edit between
  windows can move an image across a window boundary, and the gallery reloads
  its windows when the catalog changes.
