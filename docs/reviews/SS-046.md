## Requirement coverage

Test files:
- **U** (core unit): `crates/core/src/image_annotations.rs`. Real on-disk catalogs,
  several connections and threads, the real register and replace paths, and
  genuine v12 schema fixtures.
- **R** (renderer): `src/ImageAnnotations.test.tsx`.
- **B** (Chromium): `e2e/image-annotations.spec.ts`, against the IPC fixture.
  **This is browser-only UI coverage, not the native webview.**

- **R1 tags, notes, favorites, ratings, rename/alias, normalization.**
  - Tags follow audio's display rules (underscores, whitespace, 64 characters, no
    control characters), plus NFC and the contract's 256-byte limit.
  - Identity is case-insensitive and the first spelling is kept.
  - Rating is 1–5 or `null`; zero is rejected. Notes are plain text, ≤ 40,000 bytes.
  - U: *tags_normalize_like_audio_with_nfc_and_explicit_limits*. Covers
    `Café` = `Café`, the 64/65-character boundary, 64 × 4-byte characters
    exactly at 256 bytes, the control character, case duplicates, case-insensitive
    removal, the 65th tag, and add plus remove of the same tag.
  - U: *ratings_notes_and_favorites_are_explicit_plain_values*. Covers ratings 0
    and 6, `null` versus absent, notes over the byte limit, NUL, and that no
    array-replacement field is accepted.
  - U: *rename_merges_in_place_keeps_aliases_and_leaves_audio_alone*.
  - R: tag splitting and the identity mirror.
- **R2 user facts separate from analysis/AI, preserved on reimport/replacement.**
  - Only the contract's `annotations` object is written. Analyses and `evidence`
    are never touched.
  - U: *replacement_reimport_and_duplicate_content_keep_independent_annotations*.
    A same-path content replacement and an unchanged reimport keep annotations and
    revision byte-for-byte. A same-hash copy has separate, empty annotations. The
    original file's BLAKE3 is unchanged after edits, rename and undo.
- **R3 optimistic revisions, explicit operations.** The patch has add, remove and
  set fields only. Single edits require the revision the editor read.
  - U: *stale_editors_get_conflicts_and_concurrent_writers_never_lose_tags*. A
    stale editor gets `CONFLICT`. Eight threads on separate connections race
    refresh-and-retry edits on one image; all 10 tags survive and the revision ends
    at exactly 3 + 8.
  - R: the editor sends `expectedRevision` and explicit patches; on a conflict it
    shows the message and reloads without retrying.
- **R4 bounded batch, preview, per-item results, reversible history, transaction
  policy.**
  - Bulk edits are limited to 1,000 items. Preview returns tokens, per-tag counts
    and skipped items.
  - One transaction covers the items and their history record.
  - Items changed after preview are `conflict` and left untouched; undo restores
    only items still at the action's revision.
  - U: *bulk_edits_preview_counts_and_report_each_item* covers offline, unknown
    and conflicting items, the dirty marker, the label, bounds, no bulk notes and
    duplicate targets.
  - U: *undo_restores_exact_prior_state_and_keeps_later_changes* covers exact tag
    order, revision +2, a later edit winning, history across a restart, and undo
    being single-use.
  - U: *a_failure_mid_batch_rolls_back_every_item_and_its_history* injects a
    storage failure on item 4 of 5, then reopens: no item changed and no history
    row exists. The same tokens then apply.
  - U: *history_is_bounded_and_pruned_oldest_first* (105 → 100).
  - R and B: preview, apply, outcome summary and undo; history undo.
- **R5 rename scope, counts, reversible alias migration.**
  - Image tags only, within the gallery scope. Aliases are library-wide and only
    from all-source renames.
  - The preview counts editable, merged, unavailable and unchanged audio.
  - Existing aliases of the old name are re-pointed, and undo reverses both.
  - U: the rename test covers in-place rename, merge, respelling, an alias target
    being rejected, the scoped-alias refusal, alias resolution on later adds, undo
    restoring tags and aliases, alias removal, and the audio tag left unchanged.
  - R: the preview text and the alias checkbox rules (disabled for one source and
    for a respelling).
  - B: rename with an alias across 234 images; 5 offline images keep the old tag.
- **R6 plain text, size limits, absent ≠ zero.**
  - U: notes are stored verbatim.
  - R: script/img/markup in notes and tags renders as text, no element is created,
    and no handler runs.
  - B: the same check with a real `onerror` payload in Chromium (`__pwned`
    undefined, no `img[src=x]`).
  - Rating: `null` versus a zero rating is covered in U and R.
- **R7 invalidation, snapshot dirty path, SS-048 payload.** Edits go through
  `UPDATE image_assets`, so the shared `image_dirty_update` trigger fires. U asserts
  the dirty counter rises on apply and not on preview. The renderer refetches
  visible windows and reloads the inspector after every change, including after a
  conflict. The payload is documented in IMAGE_ANNOTATIONS.md ("Payload for
  SS-048").
- **R8 current identity and scope.**
  - U: *scope_rules_hide_unauthorized_images*. After a file grant is withdrawn, the
    image is `PERMISSION_DENIED` for edits and absent from tag counts and rename
    previews. A non-image ID is `NOT_FOUND`. Same-content copies are independent
    (R2 test).
  - Offline originals are read-only, matching audio (U bulk test, R editor test).

## Scale and bounds (T4)

Core, macOS arm64, synthetic rows: U *bulk_and_rename_stay_bounded_at_their_limits*.

| Operation | Release | Debug |
| --- | --- | --- |
| 1,000-image bulk preview | 24 ms | 109 ms |
| 1,000-image bulk apply | 46 ms | 205 ms |
| 10,000-image rename with alias | 475 ms | 1.88 s |
| Undo of that rename | 449 ms | 1.85 s |

- History rows are 128 KB (bulk) and 1.08 MB (rename), against the 8 MiB cap.
- Image 10,001 is refused with `LIMIT_EXCEEDED` in both preview and apply.
- A maximal rename holds the catalog lock for about 0.5 s in release.

These are single-host measurements, not guarantees.

## Review findings fixed

- **Accessible names of rating radios.** The visible digit and screen-reader-only
  suffix were joined without a space ("4of 5 stars"). Each radio now has an
  explicit `aria-label` ("4 of 5 stars", "No rating (unrated)").
- **Modal focus.** `focus()` returns `undefined`, so the `??` fallback always ran
  and moved focus off the intended first field. Fixed and asserted.
- **Unsaved notes.** Escape in the inspector closed it and dropped a notes draft.
  With unsaved changes, the first Escape now leaves the field and says the notes
  aren't saved.
- **200% zoom dialogs.** Bulk and tag dialogs were taller than the screen at 200%,
  so Apply was unreachable. `vh` scales with page zoom; dialogs are now sized with
  viewport percentages and scroll internally.
- **Rename/alias rules on the client.** The client's "respelling" check now mirrors
  the core identity rule, so the alias option can't be offered when the core would
  refuse it.
- **Schema bump fallout.**
  - The legacy-fixture helper now drops the two new tables (with an emptiness
    guard). Without that, two pre-v9 migration tests collided on upgrade.
  - SS-045's v11 upgrade test asserted version 12 and the `pre-v12-` backup name.
    It now follows `SCHEMA_VERSION` and still checks the gallery index.
- **Investigated, not a defect.** At 200%, the browser test briefly appeared to
  select the wrong images. The cause was that the inspector's focus restore (one
  animation frame) arrived after the test's own focus call. The test now waits for
  the restore, as a person would. Cell focus already syncs `focusIndex` on focus.
- **Test-only.** A `beforeEach` that returned the mock was run by vitest as a
  teardown and surfaced the mocked `CONFLICT`. Braces fixed it.

## Schema, persistence and recovery (A5)

**Schema v13** adds `image_tag_aliases` and `image_annotation_actions`.
- The upgrade takes a `VACUUM INTO` `*.pre-v13-<uuid>.sqlite` backup, then applies
  everything in one immediate transaction.
- U: *genuine_v12_upgrade_adds_annotation_tables_with_a_backup*. Existing
  annotations are byte-identical and editable; the backup is v12 without the new
  tables.
- U: *v13_collision_rolls_back_and_keeps_the_v12_catalog_usable*.
- **Consequence:** as with every bump, a v12 database backup restores only with a
  v12 build.

**Restore.** Full SQLite backup and restore carries both tables.
- `validate_image_database` now also rejects unnormalized, chained or excessive
  aliases, and malformed or excessive history.
- U: *restore_validation_rejects_alias_chains_and_corrupt_history*.

**Snapshots and portable catalogs.**
- Source snapshots: dirty through the shared trigger, and still guarded until
  SS-048.
- Portable: aliases block the audio-only portable export, like image rows.
  U: *aliases_block_audio_only_portable_export_until_mixed_catalogs*.
- History is deliberately excluded from portable formats. It is local undo state,
  and the user-visible consequence (undo does not travel) is documented.

**No change.** Annotation fields are unchanged from the SS-040 contract.

**Retention.** History is bounded to 100 actions. Deleting an image leaves history
entries that report `not_found` on undo.

**Inapplicable.** AI, consent, models, export, MCP and cancellation do not apply.
The operations are bounded synchronous transactions with no long-running job to
cancel.

## Remaining limits and handoff

PR: https://github.com/nileshkant/AI-editing-asset-organiser/pull/48 (targets main). CI results are recorded on the PR for its exact head; no
merge is authorized here.

- **Not verified natively.** UI evidence is Chromium with an IPC fixture. Core
  behavior is verified on real catalogs. Not verified: the Tauri command
  round-trip in an installed build, the native webview, screen readers
  (VoiceOver/NVDA), and Windows/Linux, whose CI covers the core tests only.
- Annotations aren't shown in grid cells and there is no tag filter or search yet
  (search is SS-050). Tags appear in the inspector and the tag manager.
- Offline or missing originals are read-only, matching audio. A rename leaves their
  old tag in place and counts them.
- Undo is single-step per action with no redo, and the history is local.
- A maximal rename holds the catalog lock for about 0.5 s (release).

**Handoff to SS-047** (do not implement here). SS-047 imports individual images into
the same records:
- New images start with the contract default annotations
  (`revision: 1`, empty tags).
- A reimport or replacement must keep `annotations` untouched (U test above).
- Imported tags, if any, should go through `edit_image_annotations` semantics:
  `display_tag`, alias resolution, revision.

**For SS-048:** carry `annotations` and the alias list; exclude history; then
remove the alias portable guard.
