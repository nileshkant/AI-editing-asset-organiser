# SS-034 — compatible GTK security backport (partial)

Confirmed the Linux dependency chain: local GLib 0.18.5 → ATK/GDK/GTK3 →
Tauri/muda/Tao/WebKitGTK. The application does not directly call VariantStrIter
outside the new regression test; transitive reachability is not a reason to retain
undefined behavior. GTK3 requires GLib 0.18, so a forced 0.20 replacement would
change incompatible APIs. Adopted the upstream gtk-rs PR #1343 two-line fix:
make the C output pointer mutable and pass its mutable reference.

Provenance: crates.io glib 0.18.5 archive SHA-256
233daaf6e83ae6a12a52055f568f9d7cf4671dabb78ff9560ab6da230ce00ee5,
upstream commit 42b9caf98e03ded086362d9653ca58fe94dc8658, MIT license.
`vendor/glib-provenance.json` records every original file hash. CI verifies all
121 vendored files and reconstructs the upstream iterator file by reversing only
the exact two-line fix. Git attributes preserve source byte hashes on Windows.
All upstream APIs/version/dependencies remain unchanged; the lock changes only
GLib from registry to the local patch plus the Linux-only regression dependency.

Evidence on macOS arm64, 2026-10-02:
- Source integrity guard passed: 121 original files, precisely the reviewed fix.
- Linux dependency tree resolves all GTK callers to the patched local crate.
- Native macOS check passed. This cannot validate the Linux-only implementation.
- RustSec against the already fetched current database reports zero registry
  vulnerability entries and six unmaintained advisories; no ignore rules were added.
  Important: registry auditing skips local patched crates, so absence of the GLib
  warning is **not independent proof of remediation**. Source provenance/integrity,
  upstream review and optimized Linux regression evidence must accompany it.
- The first non-escalated test invocation could not bind loopback inside the sandbox;
  it failed MCP shutdown setup. The configured full suite is rerun with permitted
  loopback access; report the actual final result below rather than treating it as
  a product defect or claiming the sandbox pass.

CI adds an optimized Linux native regression for next/next_back/nth/nth_back/last,
repeated reads, empty/Unicode strings and wrong variant types. Its result is required
before reviewing the remediation as verified. No Linux optimized result, physical
playback, installed startup or package qualification has been claimed yet.
The Linux release block remains until the patch review and installed platform gates
are satisfied. Six proc-macro/unic maintenance advisories remain tracked: they are
unmaintained upstream components, not made maintained by this narrow patch.

Primary references: [RustSec RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html),
[upstream gtk-rs fix #1343](https://github.com/gtk-rs/gtk-rs-core/pull/1343).
