# SS-022 — settings, recovery and diagnostics

Settings now exposes output device selection, one-worker import pause/resume,
consistent database backup, confirmed restore with rollback copy, waveform cache
purge and redacted diagnostics. Folder relink/removal and source metadata
reuse/retry/rebuild are retained. AI recognition remains unavailable.

SQLite v8 adds preferences transactionally with a pre-migration WAL snapshot.
Backups stage/sync/publish without replacement. Restore verifies current compatible
schema, integrity and references, requires idle imports/exports and retains a
rollback database before SQLite backup-API copy. It stops playback/MCP, clears
pending catalog grants and marks restored incomplete jobs cancelled. Newer
source metadata survives: retained source revision checks cause an explicit
conflict instead of silently overwriting post-backup annotations. Restart and
metadata review are explained in `docs/RECOVERY.md`.

Waveform maintenance serializes against builds and only removes generated
hash-named regular files. Diagnostics are an allowlist of versions, platform,
engine availability and counts; no paths, names, annotations, logs or credentials.
No upload exists. Named device selection persists. Production output failures
now report an error instead of silently using the test-only loopback sink.

Validation on 2026-10-02:
- Frontend: 131 tests across 12 files passed; TypeScript/Vite build passed.
- Native command compilation passed with existing vendor Tao warnings.
- Recovery fixtures cover WAL metadata/preferences roundtrip, rollback,
  incompatible/hostile schemas, backup collision/failure, active imports,
  redaction, cache isolation and v7→v8 pre-upgrade backup.
- Source fixture confirms an old restored database cannot replace newer source
  annotations; unavailable native output returns an error with no loopback.
- Worker fixture verifies queued work waits while paused and runs after resume.
- Full workspace fixtures with explicit FFmpeg tools and loopback permission: 183 passed, zero failed/ignored.

Limits: no physical device-switch/audibility, disk-full database restore,
installed upgrade/restart or long-session qualification is claimed. Backups from
a differing version/schema layout require the matching app or portable import.
Waveform clear rebuilds on demand; analysis reset is deliberately not exposed.
Source recordings and private databases were not used.

Windows CI follow-up: run 36974666998/job 110735791479 exposed a
production backup portability defect: sync_all on a read-only file handle
returns Access denied on Windows. Reopen the owned staging file read/write
before flushing. Destination publication still uses no-replace hard links.
