# SS-051 — optional local model pack lifecycle

Implementation and local review: 18 November 2026, branch
`claude/project-thread-bcnmon` from main `3cbad00` (SS-050 and SS-080 are merged,
so this PR targets main). Design, manifest format and limits:
[MODEL_PACKS.md](../MODEL_PACKS.md). Rationale: [DECISIONS.md](../DECISIONS.md)
("SS-051 model packs").

**Scope decision carried from SS-050.** No local image model has passed the
evaluation, and this environment has no model, runtime or hardware to run one.
The lifecycle is built and tested end to end against generated pack files, and the
trusted manifest ships **empty**. The settings page says so plainly. T3 (real
inference) and A3's measured pack footprint for a real pack are therefore open.

## Requirement coverage

Tests: **P** `crates/core/tests/model_packs.rs` (22), **R**
`src/ModelPackSettings.test.tsx` (7), **E** `e2e/workspace.spec.ts` (settings
accessibility and overflow, with a pack row added to the fixture).

- **R1 versioned allowlisted manifest.** `Manifest::parse` is strict
  (`deny_unknown_fields`, version 1, 64 packs, 64 files, 16 GiB) and records id,
  version, capability, pinned embedding space, HTTPS origin and allowed hosts,
  license and notice, requirements (os, arch, CPU features, RAM, accelerator,
  runtime), exact sizes and BLAKE3 digests. Disk guidance is derived from the
  sizes. The bundled list is compiled in.
  - P: *manifest_rejects_untrusted_or_malformed_entries*,
    *bundled_manifest_is_valid_and_offers_no_unqualified_pack*.
- **R2 controls and states.** Download, resume, cancel, discard partial,
  activate, deactivate, uninstall (confirmed), with progress and disk preflight.
  States: not installed, downloading, verifying, verified, active, failed,
  incompatible. "Downloaded" and "verified" are one step here: each file is
  verified as it streams and nothing is installed until all pass.
  - P: *install_verifies_every_file_then_activation_reverifies*,
    *not_enough_disk_is_refused_before_any_download*,
    *cancellation_keeps_a_resumable_prefix_and_is_not_a_failure*,
    *only_one_install_runs_at_a_time*. R: the download, progress, failure,
    incompatible and removal tests.
- **R3 integrity, authenticity, safe staging.** Authenticity is the compiled-in
  allowlist: only files whose size and digest are listed there can install, from
  listed hosts. Staged in `staging/`, moved with one atomic rename, activation
  re-hashes. There is no archive format, so there is no archive traversal or link
  to reject; manifest paths are validated and a link planted where a partial file
  goes is removed, not followed. Nothing downloaded is executed.
  - P: *wrong_digest_wrong_size_and_overlong_bodies_never_install*,
    *a_planted_link_where_the_partial_file_goes_is_not_followed* (Unix),
    manifest path cases.
- **R4 bounded network, validated resume, prior pack kept.** One install at a
  time, 10 s connect, 60 to 90 s per request, 8 MiB range slices, at most three
  redirects, all to allowlisted HTTPS hosts. Resume only on identical recorded
  URL, size, digest, ETag and a matching `Content-Range` total. An update installs
  beside the working pack.
  - P: *truncated_download_resumes_with_a_range_and_verifies_the_whole_file*,
    *resume_restarts_when_the_file_identity_changed_or_ranges_are_ignored* (ETag
    change, ranges ignored, 416),
    *redirects_only_go_to_trusted_https_hosts*,
    *an_update_never_disturbs_the_working_pack_until_it_is_activated_and_can_roll_back*,
    *the_http_fetcher_resumes_with_ranges_and_never_follows_redirects_itself*,
    *a_full_install_over_the_real_fetcher_to_a_loopback_origin*.
- **R5 unsupported hosts do not break the base app.** OS, architecture, CPU
  features, accelerator, runtime, low RAM are distinct typed reasons; unreported
  RAM is shown, not guessed. Missing files and corrupt state are handled at
  startup. An incompatible pack is never downloaded.
  - P: *incompatible_hosts_are_reported_without_breaking_anything*,
    *unreported_memory_is_shown_not_guessed*,
    *startup_is_offline_and_survives_missing_files_corrupt_state_and_orphans*,
    *the_base_app_needs_no_pack*.
- **R6 active-pack changes are version changes.** Activation bumps a persisted
  `generation`; leases carry `space_id` and `generation`. Switching an embedding
  pack to a different pinned space records a pending reindex and mixes nothing;
  same space needs none. Annotations and exports are untouched.
  - P: *an_update_…_roll_back*, *packs_with_the_same_pinned_space_switch_without_a_reindex*.
- **R7 safe uninstall.** Leases block replacement and removal (`InUse`), new
  leases are refused while draining, the wait is bounded, only the pack's own
  folder is deleted (inside the store, never a link), state is saved before
  files are removed, with a storage summary and per-pack usage count.
  - P: *running_tasks_block_replacement_and_removal_…*,
    *uninstall_deletes_only_what_the_pack_owns_and_reports_storage*.
- **R8 SS-017 reuse.** No pack code existed, so this is the shared subset.
  [SS-017](../../tickets/SS-017.md) links it; its audio criteria stay open.

T1 is covered by the P tests above except a real ENOSPC during a write (the disk
check is tested; the write-time error is mapped but not provoked). T2 is covered by
update, rollback, uninstall under load and offline restart; "queued" jobs do not
exist until SS-052, only leases. T3 is open.

## Findings from my own review, and fixes

1. Progress counted a restarted file twice; it is reset to the pre-file value.
2. `activate` could race `uninstall` and activate a removed pack; the commit now
   rechecks the record. (Fixed; no deterministic test, the window is two lock
   holds apart.)
3. A planted link at a partial path would have been followed; now removed first
   (tested).
4. Overview recomputes folder sizes on every 1 s poll; it only lists metadata, so
   left as is.

`space_id`, `generation`) and `pack_dir`. It must stamp results with the lease
identity and treat a changed `generation` as a replaced model. It needs to ship
the first inference runtime (`System::runtimes`) before any pack can install.
