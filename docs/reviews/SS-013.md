# SS-013: Clip export and handoff review

Reviewed locally on macOS on 2026-10-02. Implementation is awaiting PR review and merge; this is not a production release qualification.

## Delivered behavior

Saved clips can export to an explicitly chosen native save-dialog destination. WAV / 24-bit PCM is the default; FLAC, source-rate preservation, 44.1/48/96 kHz conversion and fade controls are available. Stored recipe gain and channel mapping are applied. Source-frame trim precedes rate conversion; the exclusive end and nearest output-frame length are enforced. No source audio is modified.

A short-lived, one-use destination grant binds IPC to the chosen canonical filename. Arbitrary paths, grant substitution/reuse, stale revisions, changed source hashes, unknown channel policies, mismatched extensions, invalid rates and oversized fades are rejected. Both destination and sidecar collisions are denied, including symlinks. Full source identity is checked before and after encoding.

Rendering and verification run on a blocking worker outside the catalog mutex. One concurrent export bounds resource use. FFmpeg uses one decoder thread, stream reads use fixed buffers, hashes use 64 KiB chunks, and analysis uses the existing bounded waveform measurement. The frontend prevents duplicate submissions and refreshes search after indexing.

Temporary media is decoded and measured before publication: frames, sample rate and channel count must match. Short decode is never concealed with silence padding. Temporary files are synced, then no-replace hard links publish the manifest and verified audio on the destination filesystem. A racing writer cannot be overwritten. Errors and cancellation clean owned staging files. The completed audio is the cancellation boundary: cancellation arriving afterward does not remove a usable export.

Journals precede staging and support restart cleanup, including an orphaned sidecar if interruption occurs between sidecar and audio publication. Cleanup visits only known files in a UUID-named staging directory, ignores corrupt/unowned journal records, rejects staging symlinks and retains journals when the destination is offline. Completed exports remain available after interruption; import the destination folder if a crash prevented catalog indexing.

Exports enter the ordinary sound catalog with measured profiles, clip names and provenance comments. Analysis, sound and annotation publication uses a transaction; existing annotations survive repeated indexing. Watched-source exports reuse the existing scope; reimports reuse the file identity. A catalog error leaves the verified media intact and returns a separate indexing warning.

Each output has an adjacent `.soundshelf.json` manifest with a relative media filename, source ID/hash, exact recipe, revision, effective fades, format/rate options and output hash/frames/channels. It omits absolute source paths and credentials. The UI provides the completed local path, copy action and manual editor-import instructions.

## Review findings resolved

- Unix rename can replace an existing file. Replaced it with atomic create-if-absent hard links; added a racing-writer regression test.
- Recanonicalizing a grant after a parent symlink changes can broaden its scope. Canonicalize at dialog selection and reject a changed parent at rendering.
- Padding can conceal short output. Removed padding and require the measured output length.
- Interrupted sidecar-only publication can leave a collision on retry. Compare the orphan against the still-staged manifest during recovery.
- Treating an unavailable destination as an absent staging directory loses recovery ownership. Retain its journal until the parent returns.
- Clipboard availability is not guaranteed in every webview. Catch synchronous and asynchronous copy failures.
- The expanded fixture run exposed a playback test racing the decoder: it requested 4,800 stereo frames after waiting for only one sample. Wait for the full 9,600-sample buffer before asserting consumed position and resume output. No playback behavior was changed.
- Reindexing must preserve user edits. Transactional publication retains existing annotations and provenance remains searchable after ordinary reimport.

## Migration and rollback

No schema migration or new dependency. Existing schema v4 stores rendered variants as ordinary sounds. Reverting code leaves existing media/catalog data readable. Export journals and sidecars contain no credentials or source media copies.

## Limits and remaining platform qualification

- Actual Windows/Linux runs and cross-platform CI results are pending. Unix process/symlink/encoder fault injection tests are Unix-only; portable precision/catalog/recovery fixtures run on every CI platform.
- Disk exhaustion is injected as an encoder failure; the user's disk was not filled. Parent directory replacement is guarded, but a hostile local process continuously replacing directories is outside this desktop workflow's threat model.
- The destination filesystem must support hard links (APFS, NTFS, normal Linux filesystems). Unsupported/removable filesystems fail safely; no overwrite-prone copy fallback is used.
- Native save dialog and clipboard wiring compile and have IPC/UI tests; this review did not automate the OS dialog or a third-party editor. Real media files independently decode with FFmpeg and are usable without the app. Follow `docs/CLIP_EXPORT.md` for editor smoke tests.
- Native drag-out, editor-specific timeline placement, reveal-in-file-manager and persistent export history are later integration work. This ticket provides native destination selection, local path copying and manual file import.
- Cleanup retries for an offline destination occur on the next startup after it returns. An interrupted completed export is retained; if indexing did not finish, import its folder. There is no automatic render retry that could surprise-write to a user folder.
- Files are synced before publication; sudden machine power-loss durability on every filesystem is not qualified. No long-file playback/export stress benchmark was run, so resource bounds are implementation guarantees rather than measured platform latency claims.

## Windows CI follow-up

The initial PR checks passed on macOS and Linux. Windows installed FFmpeg, then failed six media fixtures because Git Bash exported POSIX-style executable paths, which native Rust did not recognize. The Windows media-test step now uses PowerShell `Get-Command ... .Source` to supply native executable paths. All fixtures remain enabled. Temporary media is also opened with write access before `sync_all`, as Windows `FlushFileBuffers` requires that access. The Unix-only timeout import is scoped to the Unix fault tests.
