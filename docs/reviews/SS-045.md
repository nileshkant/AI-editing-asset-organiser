# SS-045 — image gallery and inspection workspace

Implementation and local review: 19 October 2026, branch
`feat/SS-045-image-gallery-and-inspection-workspace` from reviewed main `6f02e4b`
(SS-044 merged through PR #46, all checks passed on its head `35b5160`). Production
image capability stays disabled. The Images view appears only in the

## Requirement coverage

Test files: core unit `crates/core/src/image_gallery.rs` (U), renderer
`src/ImageGallery.test.tsx` (R), Chromium `e2e/image-gallery.spec.ts` (B, browser
with the desktop IPC fixture; **browser-only coverage, not the native webview**).
Previews reuse the SS-044 service, which is covered by real-worker integration tests in
`crates/core/tests/image_preview.rs`.

- **R1 navigation, paginated grid, audio preserved.** Sidebar "Images" item (shown
  only when images are enabled or exist). New commands are `image_gallery_page`
  (windows of 1–100, offset ≤ 100,000) and `image_details`. `useAudioSearch` keeps
  the last audio page's query while Images is shown, and the audio selection is not
  cleared by the switch. B: *switching to images keeps the audio list, selection,
  details and playback*. It covers the selected row's inspector on return, an
  unchanged transport, no pause from Space in the grid, and no reset audio search.
- **R2 size, windowing, deterministic sort, selection by ID.** Thumbnail sizes are
  96/144/208 px. Only visible rows plus one overscan row render, and at most 12
  windows of 100 stay in memory. Sort is case-folded path, then exact path, then
  ascending ID, in both directions. U: *windows_are_deterministic_case_folded_and_tie_broken_by_id*
  (stitched windows equal one full read, same-name tie-break by ID, scope and
  invalid bounds). R: *keeps selection by identity across source and sort
  changes, and clears it after a restore*; *fetches windows on demand, fences a
  late reply after a query change, and bounds memory*; *resumes a byte-capped
  short window and refreshes without dropping visible items*.
- **R3 inspector, fit/100%/zoom/pan, compare.** Facts include oriented and stored
  size, EXIF orientation, format, bytes, bit depth, color handling, file, source,
  availability, technical and AI state ("Not enabled"), and read-only tags. Fit uses
  the inspect tier. Zoom levels are 25–400%, plus 100%. Above the inspect scale the
  viewer requests 512² 1:1 tiles for the visible viewport only (≤ 48). Pan works by
  drag or arrow keys. Compare shows 2–4 images in a modal. R: *zooms between fit and
  bounded 1:1 tiles*; *enables comparison only for 2–4 selected images*. B: inspector
  facts, the 100% button issuing ≤ 48 tile requests, and the compare dialog with
  two images, at three layouts.
- **R4 transparency and backgrounds.** Channel support and actual transparent
  pixels are reported separately: no alpha / alpha but opaque / binary / partial.
  Checkerboard, light and dark are CSS backgrounds on the viewer and in compare;
  image bytes are never changed. R: *distinguishes channel support from actual
  transparency*. B: selecting Dark applies `bg-dark` to the viewer, and the text
  reads "Partial transparency · semi-transparent pixels".
- **R5 states.** Covered states:
  - no sources and no supported images (with the Add actions);
  - import running and partial failures (with "Review in Imports");
  - loading and listing errors;
  - per cell: pending and failed analysis, and offline originals;
  - in the inspector: unavailable originals;
  - stale previews, where `STALE_VERSION` refreshes the visible windows.

  Cache rebuild needs no special state. A cleared or rebuilt preview cache is a
  miss that the service regenerates, and the cell shows loading until then. A
  failed or pending item never shows a ready preview. R: *explains no sources,
  empty views, running imports and partial failures with actions*; *labels pending,
  failed and offline items*; *shows offline and failed states without a false ready
  preview*; *does not request uncached 1:1 tiles when the original is offline*.
- **R6 accessibility.** The grid is an ARIA `grid` with row/column counts and
  `aria-multiselectable`. Focus is a roving tabindex. Keyboard support:
  - arrows, Home/End, Ctrl/⌘+Home/End and PageUp/PageDown move;
  - Space selects and Enter opens;
  - Escape closes the inspector and returns focus to the cell;
  - in compare, focus is trapped and Escape returns focus to the button.

  Cells have descriptive labels covering name, size and status. Controls have
  tooltips, and reduced motion is respected. R: *moves by arrows, rows, Home/End
  and pages; Space selects and Enter opens* (stateful harness that checks real DOM
  focus). B: the whole flow by keyboard, with axe WCAG 2 A/AA + 2.1 AA showing zero
  violations on the gallery, inspector and compare at each layout.
- **R7 cancellation and bounded handles.** Each thumbnail waits 120 ms after mounting
  before requesting. Unmounting or a prop change cancels requests in flight and
  revokes owned blob URLs (SS-044 `ImagePreview`, extended). Window replies use
  query-generation fencing, so late replies can't replace newer data or change
  selection. R: late-reply fencing test above. B (100K): 0 preview requests while
  scrolling, and 21 after settling for 22 rendered cells.
- **R8 layout.** B at 1280×820, 720×560 and 1280×820 with 200% page zoom: no
  horizontal overflow with long Unicode names, and screenshots inspected. The layout
  uses a container query, because viewport media queries ignore page zoom. The
  thumbnail tier is chosen from cell size × `devicePixelRatio`. Loading during an
  import is covered by the R5 banner tests and the refresh-without-drop test.

## Review findings fixed

- **Windows full-catalog sort (CI-class risk).** A first query sorted all registry rows
  per window: 556 ms at 100K. Fixed with a key-only window CTE, a per-source count
  using the existing `(source_id, kind, id)` index, and the v12 expression index.
- **Files-scope fixture.** Bulk insertion created image rows for every source and
  tripped the scope trigger. The fixture is now scoped to its source. The test still
  proves a registry-only sibling outside the grant is excluded.
- **Grid rendered stale data.** The memoized grid didn't rerender when a window
  arrived. It now takes a cache `version` prop.
- **Preview storm.** Fast scrolling issued 3,094 preview requests. The 120 ms
  mount delay brought this to 0.
- **Hidden-grid measurement.** A 0-size ResizeObserver reading fell back to 800 px
  and caused overflow. Zero readings are now ignored.
- **Focus loss.** A column change re-created the focused cell and focus fell to
  `body`. A native `focusout` listener now focuses its replacement.
- **200% zoom overflow.** Media queries don't respond to page zoom. The layout now
  uses `@container image-workspace (max-width: 700px)` with `minmax(0, …)` tracks.
- **Compare radios stacked vertically.** Fixed with inline-flex labels.
- **Weak keyboard test.** The first version mocked `setFocusIndex`. It was replaced
  with a stateful harness that asserts `document.activeElement`.
- **CI: scale test counted the first screen as scroll work.** On the slower CI runner
  (frame p95 34 ms), the first screen stayed mounted past 120 ms before the test
  started scrolling. Its 29 thumbnail requests were counted as "during scroll" and
  the test failed: 29 ≠ 0. Reproduced locally at 6× CPU throttle with exactly
  29 + 21 = 50 requests, none from intermediate positions. Product behavior was
  correct; the measurement was not. The test now waits for the first screen, takes
  its count as a baseline, counts requests inside the scroll loop, and asserts every
  later request belongs to a final visible cell.
- **CI: Windows FFmpeg install (infrastructure).** In the first PR run,
  `choco install ffmpeg` got HTTP 503 from the Chocolatey community feed, so both
  Windows jobs failed before any test ran. Nothing changed in the code or the
  workflow; the result is from the rerun on the same head.

## Schema, persistence and recovery (A5)

`SCHEMA_VERSION` changed from 11 to 12. Only one index was added:
`asset_registry_gallery(kind, lower(relative_path), relative_path, id)`; no table or
column changed. The upgrade path is unchanged: a consistent `VACUUM INTO`
`*.pre-v12-<uuid>.sqlite` backup, then the index and `user_version` in one immediate
transaction. U: *genuine_v11_upgrade_adds_only_the_gallery_index_with_a_backup*;
*v12_collision_rolls_back_and_keeps_the_v11_catalog_usable*. **Consequence:** as
with every earlier bump, full database restore accepts only backups of the same
schema version. A v11 backup can't be restored into a v12 build; restore it with
the v11 binary before upgrading. Portable JSON and source snapshots are unaffected.

Permissions: listings are scoped to the local desktop owner's registered sources.
File-scoped sources return only granted members. Responses carry relative paths only,
with no absolute roots, evidence or recipes. Renderer state (thumbnail size,
background, selection) is session-only and isn't persisted. Selection clears on
`image-import-reset` (database restore). Revision and invalidation: content hash and
annotation revision come with each summary; `STALE_VERSION` refreshes the windows.
Not applicable here: AI, consent, models, export, MCP and editing (none added). No tag
editing, search, export or file removal is offered or advertised.

## Remaining limits and handoff

PR: https://github.com/nileshkant/AI-editing-asset-organiser/pull/47 (targets main). CI results are recorded on the PR for its exact head; no
merge is authorized here.

- **Not verified natively.** UI evidence is Chromium with an IPC fixture. Real
  previews come from the SS-044 native service tests, not from an end-to-end run
  in the native webview. High-DPI tier selection is unit-level only, with no
  physical display check. Installed builds, VoiceOver/NVDA and Windows/Linux
  webviews are not verified.
- The audio list remounts on return, so its scroll position within the current
  75-item page isn't restored. The query, offset, selection and playback are.
- Windows are live observations. An import between two windows can shift offsets
  (a duplicate or skipped cell until the debounced refresh). Selection is by ID and
  never shifts.
- Tiles decode the full image per tile (SS-044). Measured panning with ≤ 48 visible
  tiles was acceptable in the fixture; a batched tile job is not needed yet.

**Handoff to SS-046** (do not implement here). The interfaces SS-046 consumes:
- `useImageGallery().selected`: a `Map<id, ImageSummary>` that survives source and
  sort changes and clears on restore.
- `ImageSummary.annotation_revision` and `image_details(id).tags/caption` for
  read-before-write revision checks.
- The read-only tag list in `ImageInspector`, which SS-046 replaces with its editor.
- `image-import-reset` and the debounced `refresh()` for reloading visible windows
  after bulk edits.
