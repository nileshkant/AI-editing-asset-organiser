## Requirement coverage

Test files:
- **I** (core integration, real HTTP and TLS servers on loopback, real SQLite):
  `crates/core/tests/ai_provider.rs`.
- **D** (desktop): `src-tauri/src/providers.rs`, test

- **R** (renderer): `src/AiProviderSettings.test.tsx`, `src/SettingsView.test.tsx`;
  **E** (Playwright): `e2e/workspace.spec.ts`.

- **R1 configuration and capability registry.** `ProviderProfile` stores kind,
  endpoint, model, local opt-in, key storage and a revision; `Capabilities`
  records image input, structured output and embeddings as untested, supported,
  unsupported or inconclusive, plus the tested revision and served model.
  Locality (this computer, private network, internet) is derived from the
  endpoint. Text support implies nothing about images.
  - I: *four_wire_contracts_verify_capabilities_from_observed_answers*,
    *text_only_models_are_unsupported_for_images_not_authentication_failures*.
- **R2 SS-014 reuse.** No SS-014 code existed, so the shared subset is built here
  once (`ai_provider.rs`, `ai_provider_wire.rs`). [SS-014](../../tickets/SS-014.md)
  links this evidence and keeps its own criteria unchecked.
- **R3 key storage.** OS keychain (macOS Keychain, Windows Credential Manager,
  Linux Secret Service via `keyring` 3.6.3) or process memory. Keys are only an
  input to `ai_provider_set_key`; no command returns them, and the IPC copy is
  zeroed after use.
  - I: *configuring_providers_and_keys_makes_no_requests_and_never_stores_keys_in_the_catalog*
    searches the raw database file, `app_settings`, the support report, a
    portable export, serialized views and `Debug` output for the key.
  - D: real round trip, read back and delete in GNOME Keyring (Secret Service)
    on Linux; without a Secret Service the same test asserts the typed
    `KEYCHAIN_UNAVAILABLE` error. macOS and Windows run it in CI.
  - R: the key field is a password input that clears after saving and is never
    filled from the backend.
- **R4 endpoint policy.** HTTPS for remote endpoints with platform certificate
  verification; explicit opt-in for loopback and private endpoints; link-local
  (including cloud metadata), multicast, broadcast, unspecified and reserved
  addresses are always refused; every resolved address is checked when
  connecting; credentials, queries and fragments in URLs are rejected; redirects
  are never followed. Endpoints come only from settings.
  - I: *endpoint_policy_requires_https_and_explicit_local_opt_in*,
    *redirects_are_refused_and_never_followed*,
    *transport_failures_are_bounded_and_distinct* (timeout, TLS handshake
    failure, untrusted self-signed certificate, unreachable, oversized response
    and request).
- **R5 explicit connection test.** The only command that contacts a provider. It
  sends a generated 16×16 PNG and fixed text, never user files. Authentication,
  model not found, image unsupported, schema incompatible, timeout, quota and
  rate limit each have their own code.
  - I: *wire_errors_map_to_distinct_sanitized_codes*, plus the transport test.
- **R6 adapter trait.** `ProviderAdapter` (`model`, `generate`, `embed`) with
  bounded images, text, request and response sizes, output tokens and embedding
  dimensions; 10 s connect and 60 s request timeouts; sanitized errors (key and
  key-shaped tokens removed, control characters stripped, 200 characters);
  served model version and token usage. The production image adapter is
  qualified in SS-050.
- **R7 failure and change handling.** Keychain denied or unavailable leaves
  settings unchanged; rotation replaces in place; switching storage deletes the
  other copy; kind or origin changes delete the key; deleting a profile deletes
  its key first; restart keeps keychain keys and forgets session keys; every
  mutation is revision-checked; adapters are issued for one exact revision and
  never fall back to another provider.
  - I: *rotation_session_keys_and_endpoint_moves_never_send_a_key_elsewhere*,
    *keychain_failures_leave_settings_unchanged_and_restored_backups_need_the_key_again*,
    *connection_test_records_capabilities_only_for_the_tested_revision* (the
    profile is edited by another connection while the test is in flight; the
    results are discarded and the adapter for the old revision is refused).
- **R8 consent and service-owned settings.** The settings screen and
  AI_PROVIDERS.md state that a key is not consent and that analysis asks per
  source later. The renderer holds no copy of settings beyond the last list it
  was given, and reloads after any refused change. The panel mounts only when its
  tab opens, so opening Settings makes no provider call.

## Performance

Listing providers reads one settings row and never touches the keychain or
network, so Settings opens without prompts. A connection test makes at most four
requests, sequentially, each bounded by the timeouts above.

## Review findings and fixes

- A TLS test against a server that never answered was reported as unreachable.
  Handshake failures now come from a server that answers in plain HTTP and from
  a real self-signed certificate, and both map to `TLS`.
- Keychain platform errors could include the account name; only the category is
  kept.
- Deleting a profile before its key could orphan a secret if the keychain
  refused; the key is deleted first and a refusal keeps the profile.
- The full web suite caught the provider panel loading while other Settings tabs
  were open, which made unrelated tests see an extra backend call. The panel now
  mounts only on its own tab and treats a non-list answer as empty.

## Remaining limits

- No HTTP proxy support for provider requests.
- Anthropic has no native embeddings endpoint; embeddings are reported
  unsupported without a request. Its structured output is schema-instructed and
  validated, not enforced by the provider.
- The connection test costs a few tokens on paid providers.
- No real provider or local model was contacted; the wire formats are verified
  against mock servers only. Real qualification is SS-050.
- Renderer coverage is jsdom and the Playwright fixture, not the installed app.

## Handoff to SS-050

SS-050 consumes `Providers::adapter(id, revision)`, which returns a
`ProviderAdapter` for one exact profile revision or `KEY_MISSING`/`CONFLICT`,
and `ProviderProfile.capabilities` as the measured starting point. Model
qualification must use real provider evidence: either a key for an
image-capable provider or an approved local model.
