  - I: *audio_only_libraries_still_export_v1_for_older_readers*.
- **R2 bounded parsing, validation, preview, collisions, atomic import.**
  - I: *unsupported_newer_and_malformed_mixed_catalogs_fail_without_changes*:
    `…/v3` reports "written by a newer CreativeShelf". These are rejected at
    preview: v1 carrying images, an unknown field inside an image record, an
    unknown kind, an unknown source, a duplicate image ID, an image ID equal to
    a sound ID, empty version history, an unnormalized tag, an alias chain, a

    conflicts with the target database fails the import after sources and
    sounds were inserted, and every table is rolled back to empty.
  - The preview shows image counts (R: *CatalogData*). A current-family

- **R3 snapshot locking, dirty and retry, atomic replacement, read-only,
  originals untouched; SS-041 guards removed.**
  - Schema v15 rewrites the three SS-041 triggers to mark dirty without the

    and *v15_failure_rolls_back_and_keeps_the_v14_catalog_usable*.
  - U: *image_registered_by_another_connection_after_staging_stays_dirty* and
    *running_image_import_defers_folder_catalog_publication*.
  - I: *read_only_folder_keeps_working_and_reports_the_snapshot_error* (skips
    when run as root, where permissions are not enforced; it passes as a
    non-root user).
  - I: *missing_members_and_newer_sidecars_are_never_overwritten*.
- **R4 warm import without rediscovery, hashing or decoding.**
  - I: *mixed_folder_snapshot_warm_import_trusts_stats_and_flags_only_changes*.
    A same-size, same-mtime byte replacement stays ready after import, which
    proves import neither hashes nor decodes. Only the member whose stat
    changed becomes pending, and the queued job is a path-list check naming
    only that member. Release-mode time for the whole warm import: **2.5 ms**.
  - Same-stat replacement is caught by SS-047 **Verify file bytes**, unchanged.
- **R5 durable versus rebuildable.**
  - U: *every_durable_column_has_a_persistence_decision* classifies every column
    of a fresh catalog as portable, backup only (with a reason) or rebuildable.
    Stats, watch preference, root identity, jobs and undo history are backup
    only. Thumbnails, previews and search projections rebuild. No roots,
    grants, credentials or media bytes are serialized.
- **R6 WAL-consistent backup, upgrade recovery, reconciliation, restore preview.**
  - I: *wal_backup_captures_committed_image_edits_from_another_connection*.
  - I: *restore_preview_is_bound_to_the_previewed_bytes*: a backup edited after
    preview is refused and no rollback file is written.
  - I: *missing_members_and_newer_sidecars_are_never_overwritten*: after
    restoring an older backup, the next folder save reports a revision conflict
    instead of overwriting newer image annotations in the sidecar.
  - R: *RecoverySettings* covers preview, confirm and cancel.
- **R7 bounded sizes and counts, no truncation, missing media documented.**
  - Limits in MIXED_CATALOGS.md ("Limits"). Exceeding any fails the operation.
  - I: *unmapped_sources_import_offline_and_keep_image_facts*.
- **R8 hooks so later fields cannot ship only in SQLite.**
  - The inventory test above, plus *portable_image_payload_names_every_portable_image_field*.
- **R9 gated local exposure, no unimplemented AI/MCP advertised.**
  - `scripts/release.mjs` no longer refuses `build` with

## Review findings and fixes

- Warm reimport of a mixed folder initially went to the audio lane, whose
  trigger conflicts with image jobs. Mixed folders now go to the image lane,
  which also analyzes pending audio.
- A snapshot save after an image re-check had no audio-style scan evidence, so
  changed members were refused. The exact `asset_file_stats` row is now the
  verification proof.
- The background saver could publish mid-import. It now also skips folders with
  queued or running image jobs.

## Remaining limits

- Not verified in the installed app or native webview; renderer coverage is
  jsdom. Disk-full during snapshot and restore relies on the existing staged
  atomic write paths and their earlier tests, not new fault injection.
- On a new machine, the first Check files rehashes each member once, because
  stats are machine-local.

## Handoff to SS-049

SS-049 starts from this head. It consumes no image persistence interfaces
directly, but any provider or model setting it makes durable must be classified
in `mixed_catalog::persistence_inventory`, and credentials must stay out of
portable JSON, folder snapshots and backups' portable paths. AI evidence it
later produces travels in `ImageAsset.evidence`, which v2 already carries.
