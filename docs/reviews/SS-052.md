# SS-052 — consented image enrichment queue and usage budgets

Implementation and local review: 20 November 2026, branch
`claude/project-thread-bcnmon` from main `ff1cefc` (SS-051 is merged). Design and
user-facing rules: [IMAGE_ENRICHMENT.md](../IMAGE_ENRICHMENT.md). Rationale:
[DECISIONS.md](../DECISIONS.md) ("SS-052 image analysis").

**Scope.** No real provider key or model was available, so no real model output
was produced. The queue, consent, budgets, fences and recovery are tested with a
scripted dispatcher against a real catalog and real imports, plus one test that
drives the real provider adapter against a loopback server. Generated tags and
their review UI are SS-053. Results are stored but not yet shown or searched.

Tests: **P** `crates/core/tests/image_enrichment.rs` (21), **M**
`crates/core/src/mixed_catalog.rs` (2 upgrade tests and the persistence
inventory), **R** `src/ImageAnalysisSettings.test.tsx` (7), **E**
`e2e/image-analysis.spec.ts` (3 viewports/zoom, keyboard, axe, overflow).

## Requirement coverage

- **R1 durable jobs, explicit enablement.** Six machine-local tables (schema
  v19). Consent is per source and names provider, exact revision and model; jobs
  are separate from import jobs. P: *nothing_is_sent_before_consent_and_only_for_consented_sources*,
  *consent_needs_a_tested_provider_at_the_exact_revision*. R: the Allow tests.
- **R2 disclosure and stripping.** Disclosure comes from the core and gates the
  Allow button. Only a re-encoded 512 px PNG leaves, built from decoded pixels.
  P: *originals_are_unchanged_and_the_real_pixel_path_strips_metadata*,
  *the_real_adapter_sends_one_bounded_request_per_image_and_nothing_earlier*
  (the request body holds no file name or id), *the_preview_pixel_source_sends_a_bounded_copy_of_the_exact_version*.
  Full pixels, prompts and metadata are never sent; EXIF removal is checked on
  the encoded PNG chunks, not on a real camera file.
- **R3 new imports, selected, backfill; counts; ceilings.** Estimate shows send,
  reuse, done, queued and not-ready counts and labels cost as unknown. P:
  *batch_ceilings_pause_the_batch_without_sending_more*,
  *new_imports_are_queued_only_with_the_opt_in_and_a_bounded_ceiling*,
  *a_finished_import_queues_its_images_only_for_an_opted_in_source*. R: the
  estimate test. The UI offers backfill only; `selected` is a core and command
  kind with no screen yet (no gallery selection hook in this ticket).
- **R4 atomic reservation, unknown outcomes.** P:
  *concurrent_reservations_cannot_overspend_a_ceiling*,
  *an_unknown_outcome_is_counted_never_auto_retried_and_keeps_its_identity*,
  *provider_failures_are_sorted_into_retry_pause_and_failure*.
- **R5 dedupe and reuse boundaries.** P:
  *identical_content_is_sent_once_and_reuse_respects_consent_and_model*.
- **R6 priority and bounds.** One worker, one request at a time, yields to
  imports and native tasks, 3 rate-limit attempts with backoff, 20,000 items per
  batch, 8 active batches, 100 finished batches kept. P:
  *cancel_stops_pending_work_and_interactive_work_has_priority*. Playback and
  audio jobs are not in the busy signal yet (limit below).
- **R7 fencing, revocation, restart, offline, quota, model removal.** P:
  *revocation_blocks_dispatch_and_discards_a_late_answer*,
  *a_changed_provider_an_offline_source_and_changed_content_stop_dispatch*,
  *a_new_source_generation_ends_the_batch_as_stale*,
  *an_answer_for_content_that_changed_in_flight_is_discarded*,
  *restart_turns_in_flight_requests_into_unknown_outcomes_and_requeues_claims*,
  *expired_leases_are_recovered_but_live_ones_are_not*. Shutdown stops the worker
  at its next step; a request in flight at a hard kill becomes an unknown outcome.
- **R8 no recall claim, no resurrection.** Disclosure and docs say sent data
  cannot be recalled. Late answers are discarded and counted. P: the revocation
  and content-changed tests.
- **R9 states, errors, retry, persistence.** The Batches list shows state,
  counts, usage, pause reasons, and per-item failures with retry; unknown outcomes
  need an accepted second charge. Persistence: every column is classified in the
  inventory test; restore resets consent and queued work, keeps results. P:
  *restoring_a_backup_clears_consent_and_cancels_queued_work_but_keeps_results*,
  *removing_a_source_removes_its_enrichment_records*. M: *genuine_v18_upgrade_adds_enrichment_storage_and_matches_a_fresh_schema*,
  *v19_failure_rolls_back_and_keeps_the_v18_catalog_usable*.

## Scenario and acceptance status

- **T1** met on the wire for the real adapter (zero requests before consent and
  while estimating; one per image after).
- **T2** met for the listed cases except quota exhaustion, which is covered as a
  disposition (pauses, keeps images queued) rather than a recorded provider reply.
- **T3 not met.** No simultaneous preview, audio, import and enrichment stress run
  was done, and UI responsiveness was not measured. Only the yield rule is tested.
- **T5** originals' hashes are unchanged (P). The audio suite passes.
- A1, A2, A3, A5 met. A4 met except the T3 gap. A6: native, model and platform
  limits are listed below. A7: see the PR.

## Verification run

- `cargo test --workspace --locked --no-fail-fast -- --include-ignored` on Linux
  (ffmpeg from apt): everything passed except two tests that fail only when run
  as root and pass as an unprivileged user (`real_backup_write_failure_cancels_upgrade_before_schema_mutation`,
  `read_only_snapshot_failure_is_retryable_and_member_access_denial_never_prunes`,
  run with `setpriv --reuid=65534`).
- The run caught two real regressions: the legacy-fixture helper in
  `tests/common/mod.rs` dropped the image tables by hand and did not know the
  enrichment tables, so the v7 and v8 upgrade tests failed with "table already
  exists". Fixed in the helper (it now asserts they are empty and drops them);
  both tests pass.
- `npx vitest run` 360 passed; `npx tsc --noEmit` clean; Playwright 27 of 28 in
  the full run, the one failure (`image-annotations` at 720×560) passed alone and
  in a rerun of that file, and looks like CPU contention with the concurrent Rust
  build.
- `cargo check -p soundshelf` passes with and without `image-development`.

## Findings fixed during review

- A test deadlocked by holding the catalog lock across a second lock call.
- Fixture rewrites of content hashes needed foreign keys off; confined to tests.
- The provider-changed case pauses (`PROVIDER_CHANGED`) rather than ending the
  batch; the stale consent is what forces the user to agree again.

## Remaining limits

- No real provider or model exercised; result quality is unknown.
- Busy signal covers image imports and native tasks only; audio jobs and playback
  are not included. T3 stress is open.
- The `selected` batch kind has no UI yet.
- Linux only. macOS and Windows are untested.
- Exact tested revision: main `ff1cefc` plus this branch.
