# SS-050 — image AI evaluation corpus and qualified adapters

Implementation and local review: 20 October 2026, branch
`feat/SS-050-image-ai-evaluation-corpus-and-qualified-adapters` from the SS-049
head `cc81339` (PR #52, all checks green). Design, corpus, thresholds and how to
run: [IMAGE_AI_EVALUATION.md](../IMAGE_AI_EVALUATION.md). Rationale:
[DECISIONS.md](../DECISIONS.md) ("SS-050 gated image AI and a generated
evaluation corpus").

**Scope decision (Col, 20 October 2026).** No provider key or model download
is available to this work. Col decided that AI features ship gated on a key:
visible but disabled until a provider passes its test, and real-model
measurements are recorded as pending rather than faked. The queue continues.
The real-model parts of R3, R4 and T1 are therefore open, and A1 and A4 stay
unchecked.

## Requirement coverage

Tests: `crates/core/tests/image_ai.rs` (**I**, 12 tests plus one ignored
measurement), `src/AiProviderSettings.test.tsx` (**R**), `e2e/workspace.spec.ts`
(**E**).

- **R1 corpus with provenance.** 40 generated images across watercolor,
  collage, 3D, screenshot, text, transparent, multiple objects, unusual crops
  and ambiguous, plus a flat control set. Every image's provenance and BLAKE3
  digest is in `eval/image-ai/corpus-v1.json`. Photographs are pending as a
  separate consented manifest.
  - I: *generated_corpus_is_reproducible_and_matches_the_committed_manifest*
    regenerates the corpus twice and compares every image byte and the
    committed manifest.
- **R2 labels, rubric, queries, language.** Gold tag facts with accepted
  spellings, caption required and forbidden terms, and 17 judged plus 2
  out-of-domain queries. Development and held-out splits are fixed. English
  only.
  - I: *scoring_rules_are_explicit*, *approved_inputs_only_tampered_or_unsafe_manifests_are_refused*.
- **R3 realistic adapters compared with a baseline.**
  - Implemented: one image-description adapter path that runs on all four
    provider kinds, and a text-embedding retrieval path.
  - Measured: the filename lexical baseline (held-out recall@5 0.216, MRR 0.294),
    and the runner end to end with an oracle and with a wrong model.
  - Resource limits are recorded.
  - **A real model is not measured: pending a key.**
  - I: *filename_baseline_is_measured_without_any_model*,
    *runner_scores_judges_and_respects_the_request_allowance*,
    *real_http_describe_sends_one_bounded_request_with_schema*.
- **R4 pinned documentation and versions.**
  - Pinned here: the schema (`creativeshelf.image-insight/v1`), preprocessing
    (`srgb-oriented-fit1024-png/v1`), embedding space identity, normalization,
    and the input recipe.
  - The served model version is recorded per run from the provider's answer.
  - Vendor documentation, license and price must be checked when the evaluation
    runs with a key; this review does not assume them.
- **R5 thresholds before evaluation.**
  - `eval/image-ai/thresholds.json` was committed alone in `e5e5bfb`, before
    any result.
  - The cut-off rule uses only the development split.
  - The oracle run shows the thresholds are reachable, and a wrong model
    fails them.
- **R6 bounded adapter and runner, untrusted output.**
  - Strict parse: no unknown fields, bounded counts and lengths, no truncation.
    Instructions treat image text as data.
  - One request per image with no retry. Only manifest-listed, digest-checked
    images are sent, and an explicit request allowance stops the run.
  - The runner needs explicit provider flags and never touches a catalog.
  - I: *model_output_is_validated_bounded_and_never_truncated*,
    *adapter_failures_stay_distinct_and_are_never_retried*, the runner test.
- **R7 confidence.** Evidence is `suggested` with confidence `unavailable`. No
  self-reported score is requested, and an uncertain answer suggests no tags.
  - I: *evidence_is_a_suggestion_without_invented_confidence*.
- **R8 one qualified path per advertised capability.**
  - Descriptions need image input plus structured output.
  - Search by meaning needs descriptions plus embeddings.
  - Offline tagging is `not_offered`.
  - Settings lists each feature with what it needs. A text-only model never
    unlocks image features.
  - I: *features_stay_visible_and_say_what_they_need*; R:
    *keeps image AI features visible but disabled until a key is added and tested*.
- **R9 handoffs.** Pixel preparation and consent boundaries for SS-052, and pack
  requirements for SS-051, are in IMAGE_AI_EVALUATION.md ("Handoffs").
  [SS-017](../../tickets/SS-017.md) records the overlap and keeps its audio
  criteria open.

T2 is covered by *adapter_failures_stay_distinct_and_are_never_retried*:
invalid JSON, oversized arrays, missing fields, unsupported image input,
timeout, model removal, throttling and quota are each distinct and never
retried. T3 is covered by
*embedding_spaces_never_mix_and_unrelated_queries_return_nothing*: frozen space
identity, dimension and normalization checks, and out-of-domain queries return
nothing. T1 is pending a key.

## Review findings and fixes

- The generated text glyph set lacked `V`, so the dialog said "SA E". The glyph
  was added before the manifest was committed.
- Model answers could carry extra fields such as URLs; unknown fields are now
  refused rather than ignored.

## Remaining limits

- No real model has been evaluated.
- Photographs are absent from the committed corpus.
- The caption rubric is lexical.
- The corpus is small and synthetic, so a pass on it is necessary but not
  sufficient evidence for creator images.
