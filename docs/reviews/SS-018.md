# SS-018 review evidence

Branch: `feat/SS-018-mcp-lifecycle-authentication`, based on merged main `ab3d70e` (PRs 13 and 14).

## Behavior and review

- Official `rmcp` 3.5.0 handles protocol messages; the app owns a dedicated two-thread runtime and loopback listener. Settings starts/stops/pairs/revokes explicitly. Default construction opens no socket. `AppState::shutdown`, invoked on Tauri Exit, cancels the server, joins the worker and clears pairings before stopping media work.
- Each pairing gets 244 random bits from two OS-random UUIDs. Only its BLAKE3 hash remains in the grant registry; comparisons use `subtle` constant-time equality. Tokens are shown once to the user and never included in status, discovery, catalog or diagnostics. No new database schema, catalog writes or source media mutations.
- Exact authority, Origin and bearer checks precede SDK parsing on every request; there are no credential sessions to steal. Body/count/concurrency/read-time limits are explicit. No generic filesystem/shell/SQL tools exist. Only a safe connection-status tool is enabled.
- The compiled bridge uses the SDK HTTP transport and SDK stdio codec, rejects non-loopback URLs and proxy/redirect routing, and fails with a fixed stderr message if the app is absent or pairing is invalid. Discovery carries no credential. No invisible service or second catalog is started.
- Revocation blocks subsequent requests; already accepted status calls may finish. Pairings expire on service Stop/Quit/restart. No tray behavior is enabled. Source/capability grants are deferred to SS-019 before any catalog tools become available.

## Verification

- `npm test`: 125 tests passed. Two new Settings tests exercise explicit start, pairing, secret hide on revoke, stop, invalid port and actionable start failure. Existing source-control tests isolate the new Settings child so their command-order mocks continue verifying source operations.
- `npm run build`: passed TypeScript and Vite production build.
- `SOUNDSHELF_FFMPEG=/opt/homebrew/bin/ffmpeg SOUNDSHELF_FFPROBE=/opt/homebrew/bin/ffprobe node scripts/cargo.mjs test --workspace --locked -- --include-ignored`: all workspace tests passed, including six MCP scenarios and the desktop shutdown test; no ignored fixtures remained.
- Six agent integration scenarios use real loopback sockets, SDK initialize/list/call, compiled stdio forwarding through discovery, unknown tool rejection, per-client revoke/isolation, restart invalidation, stop/drop listener closure, occupied port, client bounds, Host/DNS rebinding, Origin, missing/bad token, URL credential, oversized/malformed JSON, unsupported HTTP protocol version and legacy negotiation. Discovery, status, response and bridge stderr assertions check secret absence.
- Desktop state integration proves shutdown clears pairings, removes discovery and closes the listener without starting MCP by default.

Review fixes: serialized lifecycle fixtures after a parallel test reused a just-released ephemeral port; the isolated shutdown check passed, and serialization prevents fixtures from claiming each other's listeners. Malformed JSON returns the SDK's explicit HTTP 415 response. Loopback tests require execution outside this environment's listener-blocking sandbox; no negative-path fixture was skipped.

## Limits

Native installed-app Quit via each platform's menu, tray integration, signed installer bridge packaging, client-specific configuration adapters, long-term secret storage and full performance/security qualification are not claimed. Full Quit is covered through the same AppState shutdown handler, not a physical menu automation. Existing vendored tao warnings are unchanged. Cross-platform results will be recorded after CI on the exact PR head.
