# SS-005: Measured profiles and descriptions review

## Scope

Implemented full-file per-channel audio metrics, channel layout identification and normalization, provenance-aware natural language summaries, underscore-free acoustic tags, and strict profile validation.

## Changes

1. **Catalog Profile Structure (`crates/core/src/catalog.rs`)**:
   - Added `channel_peaks: Vec<f32>`, `channel_rms: Vec<f32>`, and `channel_layout: String` to `Profile`.
   - Used `#[serde(default)]` to guarantee backward compatibility with previously persisted analyses.
   - Enforced strict validation: channel metrics dimensions must match channel count, sample values must be finite and non-negative, tags must have no underscore separators, and descriptions must not be empty.

2. **Per-Channel PCM Measurement & Layout Detection (`crates/core/src/media.rs`)**:
   - Added `normalize_layout` converting probe stream layout entries (`mono`, `stereo`, `5.1(side)`, `7.1`, `quad`, etc.) into clean display names (`mono`, `stereo`, `5.1 surround`, `7.1 surround`, `quadraphonic`).
   - Extended `measure_pcm` to calculate per-channel peak and RMS alongside combined waveform extrema and overall metrics. Antiphase stereo preserves real energy on both channels without downmix cancellation.
   - Handled silence explicitly: outputs `silent` texture and uniform silent level description with `silence` and `quiet` tags.
   - Provenance disclosure is explicitly retained: `"Measured across the full recording; the event itself has not been identified by listening."` No pitch inference from zero-crossing rate and no fabricated semantic event identities.
   - Zero underscores in any generated tags.

3. **Frontend Presentation (`src/api.ts`, `src/App.tsx`)**:
   - Updated TypeScript `Profile` type with optional `channel_layout`, `channel_peaks`, and `channel_rms`.
   - Updated inspector audio facts to display accurate channel layouts (`mono`, `stereo`, `5.1 surround`, etc.) alongside duration and sample rate.
