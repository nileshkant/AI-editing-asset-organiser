# SS-020 — editor handoff and agent workflow

A standalone `creativeshelf-handoff` utility verifies an already exported pair
and emits Remotion props with public-relative paths, sample duration, clip
revision and BLAKE3 provenance. It does not install, execute or assume an editor.
Existing manual export remains available. Direct Resolve automation is deferred;
no universal codec/editor capability is advertised. Audio presets remain SS-033.

The repository skill searches and inspects scoped MCP results, requires actual
listening evidence and license confirmation, uses versioned clip recipes and
native-approved export destinations, polls completion and preserves retry keys.
It explicitly explains missing AI recognition and MCP playback capabilities.
Metadata is treated as data; no shell fragments are generated from titles.

Validation on 2026-10-02:
- `cargo test -p soundshelf-core --test handoff_scenarios --test export_scenarios
  -- --include-ignored` with real FFmpeg tools: 20 passed, none failed/ignored.
- A real rendered 48 kHz half-second clip produces 24,000 sample frames, retains
  identical props after relocation, and resolves after the original is removed.
- Tests reject traversal, outside-root symlinks, FIFOs, oversized/newer manifests,
  unsafe frame counts, changed content and output collisions.
- Manual skill frontmatter/workflow inspection completed. Bundled quick_validate
  could not run because PyYAML is absent in both available Python runtimes;
  this is documented rather than reported as a passing validator.
- APIs checked against official Remotion staticFile and Html5Audio documentation.

No Remotion preview/render or physical editor import has been qualified. The
adapter’s path/hash contract is tested; target-client walkthrough and playback
remain installed tester-release checks in SS-031. The existing scoped MCP test
suite already covers the tools described here; it is not an independent agent
evaluation. No source media or private catalog was used.
