# SS-062 — exact duplicates (first half of exact duplicates and variation families)

Implementation and local review: 20 October 2026, branch
`claude/ss-062-exact-duplicates-ybfgv1` from reviewed main `31bb956` (SS-048 #51
and SS-049 #52 merged). Design, rules and limits:
[IMAGE_DUPLICATES.md](../IMAGE_DUPLICATES.md). Rationale:
[DECISIONS.md](../DECISIONS.md) ("SS-062 exact duplicates first").

## Scope of this PR

SS-062 is split. This PR delivers exact duplicates: identical verified content
digests, reviewable stacks with creator decisions, and their persistence. The
variation-family half needs SS-060 visual retrieval, which does not exist yet,
so its requirements are **not** implemented and stay open on the ticket:

- R1 second clause (near-duplicate and variation suggestions via SS-060);
- R2 (candidate thresholds and bounded clustering of similarity);
- R3 merge and exclude-pair, which only apply to similarity groups (an exact
  stack is closed under identical bytes, so it cannot be merged with another);
- T1 re-encoded, similar-pose, opposite-expression and transitive-chain quality
  fixtures as similarity fixtures, and A2 (near-duplicate quality measurement).

Nothing in the app mentions variations or similarity; the dialog says "exact
copies" and "identical bytes" only.

## Requirement coverage

Test files:
- **I** (core integration, real PNG files, the real image worker, real catalogs):
  `crates/core/tests/image_duplicates.rs`.
- **U** (core unit, genuine schema fixtures): `crates/core/src/image_duplicates.rs`
  tests, plus `mixed_catalog::persistence_inventory`.
- **R** (renderer, jsdom): `src/ImageDuplicates.test.tsx`.
- **E** (Playwright, desktop IPC fixture): `e2e/image-duplicates.spec.ts`.

- **R1 exact identification, labeled kind.** A copy belongs to a stack when its
  BLAKE3 digest of the original bytes matches, it is an image (never an element),
  its bytes are not awaiting re-verification and it is not confirmed missing.
  Stacks carry `kind: "exact"`; the dialog labels them "Exact copies".
  - I: *identical_bytes_form_one_labeled_stack_and_lookalikes_stay_apart*: three
    byte-identical copies across two folders form one stack; the same pixels
    re-encoded with another PNG compression, a crop and a one-level brightness
    change never join.
  - U: *audio_and_elements_never_join_stacks_and_triggers_refuse_them* (a pending
    copy does not count; audio IDs are refused by triggers).
- **R2.** Deferred with the variation half (above). Exact matching has no
  threshold and no transitive chains: equality of one digest is the whole rule.
- **R3 reviewable stacks.** Representative (the preferred copy while it is a
  member, else the first available member), prefer and clear, keep separate and
  return, dismiss and show again, and compare (up to four copies in the existing
  comparison dialog). Every decision is fenced by the stack revision.
  - I: *decisions_survive_file_changes_and_report_unavailable_members* (stale
    revision is `CONFLICT`; separating the preferred copy clears it; a separated
    copy cannot be preferred; one copy left hides the stack as resolved).
  - R: decisions are sent from the read revision; a conflict reloads the stack
    without retrying; separated, new and offline copies are labeled.
  - E: the whole flow by keyboard at 1280×820, 720×560 and 200% zoom, with axe
    (WCAG 2.1 AA) clean, no horizontal overflow and focus returned on Escape.
- **R4 non-destructive.** Stacks are views. No file, path, tag, note, rating,
  revision or export is touched; the decision tables hold only digests, asset
  IDs and flags.
  - I: originals are BLAKE3-hashed before and after every scenario and match;
    each copy keeps its own notes; the image record count only grows by the one
    file the test adds. E: no delete, merge or source-removal command is ever
    sent.
- **R5 updates and durable decisions.** Membership is derived on read, so a
  refresh, relink or restore is reflected immediately. Decisions are keyed by
  digest and outlive recomputation.
  - I: dismissal hides the stack until a new identical file is found, which is
    labeled "New since dismissed"; the preferred copy's bytes change (state
    `changed`, representative falls back) and change back (rejoins with the
    decision); it goes missing after a complete scan (`missing`); the folder goes
    offline (`offline`, every member labeled); relink to the same files keeps
    every decision. U: deleting the preferred record clears the preference only.
- **R6 derivatives apart.** Elements (crops/extractions with lineage) never take
  part; cropped files are different bytes. Lineage hints remain SS-077's.
- **R7 scope.** The core API takes a source scope. Copies outside it never count,
  appear, or surface as the preferred copy; a stack with one in-scope copy does
  not exist for that caller; a scoped caller cannot override a preference it
  cannot see.
  - I: archive-only scope sees no stacks although its files have copies
    elsewhere; shoot-only scope sees a two-copy stack without the archive copy;
    an empty scope sees nothing; a scoped dismiss of an invisible stack is
    `NOT_FOUND`; a scoped prefer over a hidden preference is `PERMISSION_DENIED`.
- **R8 persistence.** Schema v16 adds `image_duplicate_groups` and
  `image_duplicate_marks`, classified in the persistence inventory. Decisions
  travel in `soundshelf-catalog/v3` and `creativeshelf-source/v3`, written only
  when decisions exist. A folder snapshot carries references to its own copies
  only.
  - I: *decisions_travel_in_catalogs_and_snapshots_never_name_outside_files*:
    full export restores into an empty library with the stack still dismissed and
    its preference and separation intact; folder `a`'s snapshot never contains
    the ID of folder `b`'s preferred copy; foreign references, wrong digests,
    duplicate decisions, v2 documents with decisions and unknown fields are all
    rejected before anything is written.
  - U: *genuine_v15_upgrade_adds_empty_decision_tables_with_a_backup* (data
    intact, existing copies stack immediately, upgraded schema equals a fresh
    one, `pre-v16` backup is a v15 database, decisions mark the folder dirty);
    *v16_collision_rolls_back_and_keeps_the_v15_catalog_usable*.

## T4 contract categories

- Authorization: R7 above. The desktop owner's scope is the gallery's source
  filter. No MCP tool exposes stacks (image MCP tools are SS-067/068).
- Concurrency: every decision is an immediate transaction checked against the
  stack revision; the renderer never retries a conflict and re-reads instead.
- Cancellation: there is no long-running work to cancel; listing is one bounded
  query plus at most 25 indexed per-stack reads.
- Persistence and recovery: R8 and A5 above.
- Resources: 25 stacks per page, 64 copies listed per stack with exact counts, a
  2 MiB page cap (short page, never silent truncation), offset ≤ 100,000, at most
  128 scopes.
- Accessibility: labeled dialog with focus trap and return, named per-copy
  buttons ("Prefer fox.png in Shoot"), a status region for totals, badges as
  text, wrapping layout at 720 px and 200% zoom (E above).

T5: no audio path changed. Audio records are refused by triggers; the full audio
suites pass unchanged; original media hashes are asserted unchanged in I.

## Performance

Measured with `crates/core/tests/image_duplicates.rs`
*stacks_stay_interactive_at_the_image_cap*: 100,000 hashed image records, 70,000
of them in 20,000 stacks of 2 to 5 copies (a deliberately duplicate-heavy worst
case), listing pages at offsets 0, 10,000 and 19,975 with exact totals, then two
decisions.

| Build | First version | Final |
| --- | --- | --- |
| Release, worst page (totals + 25 stacks) | 3.78 s | 0.19 s |
| Release, one decision | 249 ms | 9.6 ms |

The first version let SQLite drive per-digest reads from the registry's kind
index, scanning every image for each of the 25 stacks on a page. Per-digest reads
now start from the digest index (`CROSS JOIN` order, asserted with `EXPLAIN QUERY
PLAN` in the test), digests held by one record are dropped from the covering index
before any registry lookup, and totals come from window sums in the same query as
the page. The test fails above 1 s in release (5 s in debug).

## Review findings and fixes

- Per-stack reads scanned all images (above); fixed and guarded by a plan
  assertion.
- The SS-048 rule that new portable fields need a new version was first missed:
  decisions were added to v2, where an older v2 reader would have failed on an
  unknown field instead of the clear "newer version" message. They now use v3,
  written only when needed, and v2 documents carrying decisions are rejected.
- "Show more stacks" would have skipped a stack after a decision hid one; the
  next offset now counts only stacks still in the server's list.
- A scoped caller could have replaced a preference it could not see; it now gets
  `PERMISSION_DENIED`.

## Remaining limits

- Variation families (R1 similarity, R2, R3 merge/exclude-pair, A2) wait for
  SS-060.
- A copy whose bytes change and later return to the same digest gets its earlier
  separate or reviewed mark back; documented as intended (same bytes, same
  decision).
- Renderer coverage is jsdom and the Playwright IPC fixture, not the installed app.

## Handoff to SS-063 and the variation half

SS-063 can consume `Catalog::image_duplicate_groups(scope, …)` and
`DuplicateGroup.representative_id` to avoid listing several copies of one file
in collections. The variation half should add a second `GroupKind` and its own
decision storage keyed by group, reusing `PreferredState`, the scope rules and the
v3 decision pattern (a new portable version if it adds fields).
